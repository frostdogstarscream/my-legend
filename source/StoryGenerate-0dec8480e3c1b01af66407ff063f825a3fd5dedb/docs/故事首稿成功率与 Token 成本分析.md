# 故事首稿成功率与 Token 成本分析

日期：2026-10-09

## 1. 统计口径

- 首稿硬约束成功：第一次 `episode_writer` 输出即满足 Schema、审批角色和 85%–115% 文本时长门。
- 全流程首次成功：首稿不做正文局部修复，演绎与必要 Judge 后进入 READY。
- 用户主动修改大纲不算失败返工。
- Token 只按供应商 `reported` 汇总；reasoning 已包含在 output，只披露、不重复加总。
- 本项目没有经过确认的网关合同价格，因此不虚构金额。本文“成本”用 Token、调用数和耗时表达；货币成本待价格表录入。

## 2. 两例正式结果

| 指标 | 结果 |
|---|---:|
| 首稿硬约束成功率 | 2/2（100%） |
| 全流程首次成功率 | 2/2（100%） |
| 正文局部修复 | 0 |
| 网络/Provider 失败 | 0 |
| 内容硬约束失败 | 0 |
| 总模型调用 | 15 |
| reported input tokens | 51,038 |
| reported output tokens | 68,505 |
| 其中 reasoning tokens（已含 output） | 54,860 |
| 缓存读取 tokens | 2,304 |
| 总墙钟时间 | 709.98 秒 |

样本数过小，100% 不能外推为生产成功率，也不能替代 12 例矩阵。

## 3. 按节点拆分

| 节点 | Calls | Input | Output | Reasoning（含于 Output） | Provider latency |
|---|---:|---:|---:|---:|---:|
| Outline（含一次用户修订） | 3 | 8,752 | 10,462 | 7,361 | 158,674 ms |
| Episode writer | 2 | 10,688 | 15,415 | 11,669 | 265,060 ms |
| Performance annotation | 8 | 18,215 | 38,967 | 32,253 | 250,748 ms |
| Judge | 2 | 13,383 | 3,661 | 3,577 | 28,680 ms |

关键发现：演绎标注占两例 output token 的 56.9%，且 8 次调用中包含逐场调用及一次结构化 JSON 重问。即使已经切到
Fast Tier，它仍是当前最大的 Token 消耗项。应测试“整集批量标注 + 只修失败行”是否能在不降低重音合法率的情况下减少
推理输出和网络往返。

## 4. 两例差异

- Case 01：7 calls，22,098 / 32,958 Token，345.34 秒。一次 Plan、一次 Writer、四次演绎 attempt、一次 Judge。
- Case 02：8 calls，28,940 / 35,547 Token，364.64 秒。两次 Plan（第二次为用户修订）、一次 Writer、四次演绎、一次 Judge。
- Case 02 的 Plan revision 增加约 3,654 input / 3,499 output Token；这是用户主动创作行为，应在产品账单与系统返工中分列。
- 两例 Writer 都一次通过，说明前置场景预算值得继续验证；尚不能证明对 300 秒或四角色场景同样有效。

## 5. 货币成本为何未填写

仓库没有版本化的真实合同价格，且当前模型通过统一兼容网关调用。公开模型价不一定等于项目实际采购价。按设计，只有录入
`model_price_versions` 后，才能用 `llm/accounting.py` 的 Decimal 计算输出 confirmed/estimated/unknown 三类金额。
在此之前把 Token 乘任意网络价格会制造不可对账的“成本”。

## 6. 优先优化建议

1. 保持 Strong Plan + Balanced Writer，继续用真实 A/B 判断首稿质量，不因单次价格降低模型能力。
2. 优先压缩 Performance：尝试整集一次标注、限制推理输出或供应商支持的非思考模式，并保留逐行确定性校验。
3. Judge 已较便宜；在安全和连续性确定性规则增强前，不建议直接删除。
4. 为真实角色质量集补充姓名、欲望、恐惧、关系、说话习惯和知情事实；固定 12 例维持原样作为兼容基线。
5. 运行 4 例小样本后计算 P50/P95；本轮 2 例 P50 约 355 秒，没有统计意义上的 P95。
6. 完成 `004_llm_usage_ledger` 后，再提供按用户、故事版本、集、模型和日期的持久化成本报表。

## 7. 证据限制

正式证据 SHA 为 `de6fa30`。随后仅对 JSON 修复计量标签和音频预算说明做了工程收口；最终分支完整 SHA 需要重新跑至少
一个 smoke case 才能作为发布候选。当前报告不声称 12/12，也不声称人工 10/12 达到 4/5。
