# 故事创作质量前置优化 v1.6.5

日期：2026-10-10。分支：`codex/storycraft-character-ending-v2`。

## 原始样本诊断

原始文件保留在 `6-实测产物/creation_first_de6fa30_20261009/`，均为真实模型的未人工编辑输出。

- Case 01《时光发条》：大纲把“母亲的新留言”放在已经完成的爷爷告别之后，正文遵循大纲，形成突兀尾钩；爷爷的录音被写成 `narration`，演绎者因此变成旁白；大量旁白直接解释“唯一念想”“必须修好”“陷入挣扎”。
- Case 02《归位的星空》：固定样本的 Canon 只给出“角色1/角色2”，大纲和正文沿用占位名；两人说话方式相近；真相主要靠手记朗读与解释台词，学长录音再次被写成旁白。

这些问题发生在 Plan 与第一稿的输入和输出中。原自动 READY 只覆盖结构、时长、安全、连续性和逐句演绎契约，不代表文学质量已经通过人工验收。

## 本轮改动

1. `PlanContent.character_portrayals` 为每个已绑定玩具角色列出剧情称呼、行动目标、情感回避、说话方式与关系立场，随大纲供用户修改和确认。`story_name` 只是剧中称呼，不修改玩具 Canon。真实 Plan 生成器拒绝缺失人物画像、占位剧情名和大纲正文中的“角色1/人物2”。
2. `PlanContent.fictional_voice_roles` 允许大纲提议少量非玩具剧情声源，记录独立 `role_id`、剧情姓名、`performer_id`、媒介与用途。审批会把它们冻结在 Plan 快照中。Writer 只可让已批准的玩具角色或剧情声源发声；带身份的录音、电话和广播必须属于对应人物的 `dialogue`，其声道介质写入 `audio_cue_ref`。明确人物录音被伪装成旁白时，草稿合同拒绝交付。
3. 单集、非连载且 `ending_preference=auto` 的故事默认按完整短篇规划，最后一场完成行动和情感闭环，不再凭空增加新留言、新人物或新危机。连载集先完成本集局部目标，再保留有前因的长期问题。该结局契约进入确定性创作包，由 Writer 逐场执行。
4. Writer 根据已批准的人物画像区分台词，并用动作、声音与人物互动呈现知情路径；旁白只补足听觉理解所需信息。仍只允许一次完整初稿及原有的单场时长修复，不新增文学 Judge 或常态化全文重写。
5. p1.6.1 将完整短篇的结局契约前移给 Plan：最后约 15% 只承接选择、后果与回响，显式拒绝旧样本中的隐藏留言尾钩；悬疑大纲要求线索查证和机关安装路径，手记与录音只作佐证。
6. p1.6.2 进一步要求关键物件的持有与转赠权限、机关触发和去向保持一致；单现场角色减少解释性自言自语。Writer 的台词只写朗读文字，开头的括号表演提示被确定性移到 `delivery_note`，避免 TTS 念出“急促”等舞台指令。
7. p1.6.3 要求 Plan 为悬疑事件交代时间、在场人、物件移动路径，不允许嫌疑人被持续注视时完成异地动作；Writer 收束时禁止用视觉描写和旁白心理判词替代可听后果。验收脚本会保留未通过质量门的候选稿，失败错误列出具体校验项，不会把候选稿标记为 READY。
8. p1.6.4 将新审批工作流的正文 Writer 单独路由到 Strong Tier（旧 Graph 的 Writer 保留 Balanced），并在 Plan 优先选择可执行的日常行动而非玄妙机关；录音只保留生活化短句或线索，人物变化由现时行动表达。真实调用的模型、成本和效果需与 p1.6.3 并排复核。
9. p1.6.5 在悬疑 Plan 中增加小型 `mystery_causal_proof`：实际事件时间线、角色所见、行动机会、揭晓前可听线索与现场复验。新真实 Plan 缺此字段在审批前失败；获批后随大纲进入 Writer 创作包。旧 Plan 无此字段仍可读取，没有自动升级或修改 Canon。

## 兼容与边界

- 旧 Plan JSON 缺少新增数组时仍可读取，以保护历史版本；新的真实模型 Plan 必须填写当前已绑定角色的画像。
- 现有玩具 Canon、审批版本、指纹、幂等、逐句演绎和时长门没有放宽。新的剧情声源不会创建或修改硬件玩具身份。
- 角色名与表演的文学质量仍需人工评估；自动字段检查只能阻止明显占位和发声归属错误。
- `audio_cue_ref` 表示录音等介质，不代表已经完成 TTS 声纹配置；未来播放适配层需按 `performer_id` 绑定实际声音。
- 实测期间默认 Fast 路由 `deepseek-v4-flash` 返回 HTTP 404；将默认值显式改为此前结构化探测成功的 `qwen/qwen3.6-flash`。环境变量仍可覆盖；失败调用及已消耗 Token 单独保留。

## 验证口径

对同一固定输入重新经过真实 Plan→审批→Writer→演绎→校验→版本保存，保留原始 Plan、Delivery、attempt 级 Token 和时延。与原版按人物辨识度、因果、对白自然度、结局完成度、可听性五项并排复核。模型输出有随机性，两次生成不是同一获批 Plan 的严格 A/B，因此只作小样本方向性证据。
