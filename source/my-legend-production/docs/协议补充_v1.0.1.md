# v1.0 契约的实现补充

本补充随适配器 0.1.0 交付，记录实际工作流联调后确认的接口细节。原 v1.0 文档和 ZIP 保留，输入、目标及请求 fingerprint 算法保持兼容。

## 声音描述

原声音 `sound_prompt()` 会以事件 text 建立 description。如果 sound 对象又含 description，会触发重复关键字错误。适配器将制作描述写入 sound.production_description，并将原台词/声音说明逐字保留在 text；sound.constraints 保留独立约束。未修改原声音包的制作逻辑。

## 来源预检错误

请求 Schema、文件哈希、StoryDelivery/Manifest 不一致、空来源等错误发生于可追溯源行建立之前。CLI 返回退出码 2 和 `{error, state}`，其中 error 使用共同 Issue 结构；不会伪造 coverage 或 sidecar 来满足成功结果的结构。

合法来源建立之后的缺音色、缺外观、能力不支持等，仍返回原 `my-legend.adapter-result/1.0` 的 needs_context/blocked，target=null，coverage 记录 blocked。幂等键冲突属于预检错误。业务封装应处理两类结果，不把进程退出码 0 等同于媒体完成。

## 新联合模式

旧 joint_v02 的输入限制及失败行为保留。新外层对齐使用 `my-legend.joint/0.3`，消费两个独立 prepared 结果及真实文件测量所得的声音时间轴。

- 同一来源制品、版本、完整覆盖及顺序必须一致；用 sidecar 定位关联事件，检查目标文本哈希。
- 对白仍核对视觉 role；旁白分别保存音频角色与视觉无角色，不能把它们压成一个身份。
- 音效、环境和音乐可以是声音独有层；对白和朗读旁白不能被静默丢弃。
- 视觉独有动作必须有明确 duration_ms，放在来源顺序允许的间隙；不足以容纳时返回 VISUAL_GAP_INSUFFICIENT，不能挤短配音。
- 片尾纯视觉动作可产生显式静音尾段。原音轨保留，另生成派生混音并记录原/新哈希、帧数和操作。
- 背景声音可以与对白重叠，视觉主对白区间仍按当前模板顺序执行。
- 当前只支持一对一来源映射、最多 90 秒及基本素材；多重派生和更复杂动画继续返回能力错误。

输出 timing_mode 为 audio_measured_visual_actions_planned，逐事件区分 audio_measured 和 visual_planned。不能把基于声音实测的重新排轴标成动作时长也已人工确认。

## 已实现范围

首版使用 preserve 表演策略和 basic_pixel/1.0.0。精确字符停顿、逐句数值控制、enrich 锁定校验、任意人物图集及自定义皮肤均未开放；调用者明确请求这些能力时得到阻断结果。

自动化测试和本地运行使用明确标记的合成信号。普通 run-media 接口只消费显式登记的本地素材；它不新建模型任务。声音和视觉原审核点保留，预览和视频导出不触发发布。
