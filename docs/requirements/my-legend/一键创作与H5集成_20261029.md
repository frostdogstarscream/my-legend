## 持久化与接口

迁移 `002_flows.sql` 增加 `production_flows`、`production_flow_jobs`，不重写历史任务。保存 owner/work/parent、请求和素材快照、修订号、阶段、取消状态及子任务引用。

| 方法及路径（前缀 `/api/v1`） | 用途 |
| --- | --- |
| POST `/production-flows` | 创建流程，`output` 为 `script` / `audio` / `h5`；包含幂等键、creative source，H5 必须有 casting |
| GET `/production-flows` | 每作品最新流程；`work_id` 查询版本记录，`offset` 分页 |
| GET `/production-flows/{id}` | 只读阶段、结果、画外音角色及子任务 |
| POST `/production-flows/{id}/cancel` | 携带 expected_revision，阻止后续创建并取消活动子任务 |
| POST `/production-flows/{id}/resume` | 先对账再恢复；无可查询结果时保留暂停 |
| POST `/production-flows/{id}/revisions` | revise / continue / remix / audio / audio_full / stage / stage_saved |

创建唯一键为 `(owner_id,idempotency_key)`；子任务键为 `flow:{flow_id}:sound/stage`；关联表 `(flow_id,phase)` 唯一。协调器以数据库锁串行化推进/取消，创建子任务后即使关联尚未写回，中断恢复仍找回同一任务。Worker 只认流程已关联任务，不扫描恢复历史失败任务。

声音仍用 `sound_bridge/1`，视觉仍用 `asset_stage/1`。只在有效混音、实测时间轴和内容哈希验证通过后创建舞台子任务，既有视觉规划、审查和有界修复机制保留。冻结素材目录测试覆盖提交后当前目录指针变化的情况。

未知声音调用不会自动重复。用户明确确认新增费用时，可用 `audio_full` + `acknowledge_unknown_source=true` 创建独立新版本；原调用及原任务状态不变，新请求与同意快照写入新版本。该标记不能绕过其他类型任务的就绪检查，也不能将未知结果标为成功。
