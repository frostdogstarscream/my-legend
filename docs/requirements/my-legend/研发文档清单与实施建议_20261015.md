# 我的传说研发文档清单与实施建议

日期：2026-10-15。本文说明需求如何转成可以开发、联调和验收的交付物，不作为工期或上线承诺。

## 1 每类文档回答什么问题

PRD 是产品需求文档，回答为谁做、解决什么问题、用户怎样完成任务、首版做哪些功能以及怎样判定完成。原型回答界面和交互如何呈现；技术方案回答软件怎样组织；接口契约回答前后端交换什么数据。只有原型和页面数量，尚不足以约定后端、制作服务及验收职责。

| 文档 | 核心内容 | 当前情况 | 建议处理 |
|---|---|---|---|
| 产品需求文档 PRD | 定位、用户、流程、功能边界、优先级、验收、待决事项 | 本次提供 0.1 草案 | 先评审首版闭环与终端范围，确认后形成需求基线 |
| 功能清单与验收表 | 需求编号、当前状态、目标行为、验收条件 | 本次提供 24 项草案 | 拆成开发任务，并关联设计、接口和测试 |
| 页面与交互说明 | 入口、正常流程、空/加载/失败/取消/旧版本状态 | 现有 12 页原型与源码 | 补作品工作台、正文编辑、剧本/选声与任务管理；按确定范围补 NFC |
| 业务对象与数据字典 | 用户、作品、版本、角色、台词、任务、媒体、阅读/播放、额度 | 当前仅有客户端类型与历史制作契约 | 补关系、身份、归属、版本和生命周期，统一术语 |
| API 与事件契约 | 请求响应、鉴权、错误、分页、幂等、取消、任务订阅、媒体访问 | 已有客户端适配及接入建议，尚非已联调协议 | 对照实际后台形成一个正式版本，可采用 OpenAPI 与事件说明 |
| 技术方案与接入设计 | uni-app、业务后台、制作工作流、存储、队列与适配边界 | 存在历史方案和制作契约 | 更新客户端路线与复用边界，避免另建重复任务/时间轴体系 |
| 测试与验收计划 | 正常/异常、跨账户、版本变更、真实媒体、端侧、人工听审 | 有原型编译/测试记录 | 增加真实业务与真机用例，按里程碑记录结果 |
| 上线与运营说明 | 环境、配置、配额、费用观察、告警、备份、回退、反馈 | 本次未核验线上运行条件 | 在内测前补最小运行手册，发行前补渠道与发布步骤 |

首轮优先形成 PRD、数据字典、API 契约和验收计划。页面交互作为 PRD 附件，技术与运营文档随实现补充，不必为每项功能单独创建一套重复材料。

## 2 需求落到工程的方式

每项开发任务关联功能编号，并写清输入、输出、异常行为和验收证据。例如 F12“配音与局部重做”至少关联：作品工作台声音区、制作任务 API、台词/素材候选对象、局部重试规则、真实音频及人工听审用例。

状态建议区分：需求草案、范围已确认、开发中、待联调、结构检查通过、真实链路通过、人工/终端验收通过。不用一个“已完成”同时表达页面、接口和成品效果。

当前前端已有 `api.ts` 作为适配入口。先核对实际后台和制作服务，再确定哪些接口沿用、哪些需新增；不要根据原型端点名称宣称已有后台已经实现。

## 3 当前最应先统一的契约

| 问题 | 应明确的决定 |
|---|---|
| 任务命名不一致 | 当前客户端采用 `generation-tasks`；旧接入文档另有 `generation-jobs` 建议。正式契约只保留一套对外名称，历史版本通过适配或迁移说明处理 |
| 进度契约尚未完整 | 保留已有任务进度，明确作品级状态，补齐云端阅读定位与媒体播放记录及其数据来源 |
| 作品和成品版本 | 指定正文、剧本、声音和视频之间的来源关系；内容修改后标记受影响结果 |
| 角色身份与说话人 | 角色模板、作品人物、声音和视觉素材通过明确标识映射，不按名字或显示顺序推断 |
| 媒体时间轴 | 以实测素材与已确认制作结果确定时间，统一字幕和演绎引用 |
| 重试与成本 | 任务幂等、素材复用、取消边界、消耗记录及失败处理由后台统一 |
| 演示与正式环境 | 身份、作品、余额和任务来源隔离；正式失败不回退成演示成功 |

## 4 实施顺序建议

首先确认目标用户、首批终端、声音/视频范围和 NFC 是否继续作为首轮条件。之后评审 PRD 及功能清单，确定需要验证的真实样本和服务依赖。

第一轮接真实账号、作品和生成任务，补正文编辑及版本，完成云端创作与阅读。这一轮同时建设最小任务查询、额度和日志能力，以便定位后续制作问题。

第二轮接剧本、角色声音、配音和混音，完成一个短篇的可播放交付。保留原生成稿、逐句素材、选定记录与实际时长，用局部重做替代反复整篇生成。若 NFC 沿用首轮范围，可由独立验证项并行推进，角色库接口与故事选角仍共用。

第三轮接已有视频与分发能力，在真实媒体上验证人物、字幕和时间同步。自动视觉制作、商业化和社区分别评估投入，避免同时扩大成多条独立产品线。

## 5 暂不填写的内容

当前尚不能据原型可靠确定人员投入、交付日期、模型成本、正式并发量、成品时长或渠道上线时间。估算应依据可复用服务、真实模型调用、目标媒体样本与终端实测给出。

正式法律条款、支付渠道要求、内容来源授权和面向特定年龄的规则另做上线评审。本文件约定产品应提供的管理能力，不代替这些结论。
