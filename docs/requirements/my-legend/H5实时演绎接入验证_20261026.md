# 固定场景设计接入 H5 实时剧情演绎：验证记录

验证日期：2026-10-26。范围：现有 15 套固定主题场景、生活动作舞台与真实作品的接入可行性。结论为本机技术验证；尚未完成正式工作流接入或用户视觉验收。

## 结论

**可以用于人工选景后的 H5 剧情预览；尚不能作为正式视觉工作流自动产出的完整演绎结果。**

真实作品《书页里的借书卡》已用“大藏书馆”场景完整播放 77.84 秒，音频、字幕、演员、基础面部和默认对白朝向保留。场景快照、保存与恢复可用。正式工作流仍绑定旧像素素材协议，未输出当前场景引用；生活动作编排也未覆盖该作品的物件目标与翻找动作。

“大藏书馆”是对原稿“雨天旧书店内”的人工近似选景，并不证明自动语义匹配正确。原稿地点和内容未修改；雨景及书店特定陈设未逐项还原。

## 已复现的接入缺口

### 1. 正式视觉工作流没有 H5 场景协议入口

当前 `ProductionRequest.visual_profile` 仅支持 `standing_performance/1`、`pixel_performance/1`、`basic_storyboard/1`。`VisualContext.asset_pack` 固定为 `basic_pixel/1.0.0`，`SceneBinding.background_type` 只有 `indoor/courtyard/outdoor`。

离线调用实际 Pydantic 模型，分别传入 `life_v1`、`legend_scene_catalog/1` 和 `library`，均得到相应字段的 `literal_error`。这说明不能仅把新场景名称填入旧字段来接通。

正式工作流读取锁定的原生像素素材目录，生成 `VisualTrack`；H5 的 `life_v1` 另从已完成的 `StoryDelivery + AudioMix + MeasuredTimeline` 编译生活舞台。当前两条路径没有通过新的场景编排产物连接。

源码位置：

- `source/my-legend-production/src/my_legend_production/production/contracts.py:160`
- `source/my-legend-production/src/my_legend_production/production/visual_contracts.py:131`
- `source/my-legend-production/src/my_legend_production/production/visual_catalog.py:16`
- `source/my-legend-production/src/my_legend_production/production/visual_render.py:16`
- `source/my-legend-production/src/my_legend_production/production/life_preview.py:48`

### 2. 当前预览绑定整个作品的一个场景

`SceneRef` 只有 `catalog_sha256 + scene_id`，不是随时间变化的分场轨道。三个原文分场在本样本中都处于旧书店，因而可共用一个场景；这次播放不能证明多地点自动切换已实现。

源码位置：`source/my-legend-stage/src/scene-types.ts:4`、`source/my-legend-production/src/my_legend_production/production/scene_preview.py:15`。

### 3. 场景物件未接到自动行动目标

原稿两条 action：

- “两人开始分头翻找。”：现有关键词规则未生成指令，也未产生针对这条未覆盖动作的诊断。
- “墨羽停下脚步，半信半疑地走到书架前。”：只识别“停下”，在 45.24–46.5733 秒生成 `body.play / idle`；“走到书架前”报告 `AMBIGUOUS_TARGET`，没有移动到书架。

场景中确有 `bookcase` 对象，但靠近／远离规则目前只解析其他舞台演员的姓名或别名，不会查找家具对象。物件图片存在，不等于物件交互能力已经存在。新编译结果的显式朝向 cues 为 0；样本没有明确转身指令，双人默认互相面向仍在运行，不将该计数本身判为失败。

源码位置：`source/my-legend-production/src/my_legend_production/production/life_preview.py:102`，尤其目标解析约第 180 行；`performance_tracks.py:118`。

### 4. 家具互动仍受技术样例限制

新增 12 套场景的 `seats` 均为空。原有三套各有一个校准座位，但 `scene_envelope` 要求家具轨道的脚本用途为 `technical_coverage`，并核验演员、服装和动作版本；这不是可直接用于任意真实剧目的自动坐下功能。

本样本没有演出坐沙发、拿书或翻书。不能把既有家具样例的结果当作剧情动作验收。

源码位置：`source/my-legend-production/src/my_legend_production/production/scene_preview.py:114`。

### 5. 作品页入口尚未直接指定生活演绎模式

作品页“配音动作联动”仅携带 `productionId`，未携带 `profile=life_v1`；现有体验还需切换到生活动作，或使用本报告的固定预览链接。建议在正式接入时增加明确的 H5 剧情演绎入口。

源码位置：`source/fingertip-legend-app/src/pages/work/index.vue:216`。

## 建议的最小接入顺序（尚未实施）

1. 增加独立的 H5 实时演绎输出适配器：从确认后的剧本、音频和实测时间轴生成版本化舞台预览引用；固定演员目录和场景目录哈希，保留来源关系。
2. 增加分场映射表：按原文 `episode_id / scene_id` 绑定资源场景 ID，记录选择理由及近似差异。第一版允许人工审核映射，未匹配时返回待处理项。
3. 建立场景切换轨道：以实测时间轴锚定切换，覆盖前后 seek、恢复、重播与出入场状态。分场切换不能重置原音频进度。
4. 给关键物件增加明确交互锚点和能力声明：书架前站位、入口、可用座位等分别定义；将原文动作绑定到演员或物件。未覆盖的 action 必须可见地报告，不能因舞台成功播放就判为完成。
5. 用当前《书页里的借书卡》做单场景回归，再选择确实包含多个地点的已确认剧本验收换景。验收应分别检查资源加载、行动语义、时序和人工视觉效果。

第一阶段可交付目标为“人工确认分场映射后，一键生成并恢复 H5 预览”；自动家具互动、拿取物品与复杂搜索动作需独立验收。
