## 已确认的问题

### P1：外部连接故障导致剧本任务停止，分类与恢复粒度不足

第二轮的上游任务 `9f952b5e17cb4566a2a33cb93de88275` 在表演注释步骤失败，第三轮的上游任务 `b229872942a848478dca55422ec4bb89` 在大纲步骤失败。两条原始调用记录均为 `ConnectError`，不是 JSON Schema、剧情审核或时间轴错误。

当前适配器将通用连接异常包装为 `ModelUnavailableError`，usage 不可用后父工作流停为外部结果未知。此次没有自动重新提交。记录未保留更细的连接原因，尚不能确定 DNS、代理、TLS 或供应商网络故障，也不能仅凭异常名确认供应商计费情况。

建议保留经过脱敏的异常类、发生阶段、连接/发送/接收阶段与供应商追踪信息，区分能够证明未发送的请求和发送后结果未知的请求。前者可以实施有界退避重试；后者先查证或对账，不能统一无限重试。连续连接失败时暂缓新任务并显示明确原因。

### P1：原生配音 unknown 任务缺少可恢复证据

第一轮未知任务为 `raw_902c34ae82ca7bf9b9c0173b67491132adaa74f219147781400d4cd6ed4d6366`，attempts=1，没有持久化结果、可用 request_id 或对应 inflight WAV。原生适配器的通用异常分支没有保存更细的异常分类；本轮不能认定其与另两轮 ConnectError 同源。

成功的 14 条任务素材及数据库均保留。建议补齐生成请求、返回元数据、下载状态的分阶段持久化和脱敏诊断；在结果能够确认后，从失败素材续做并复用已成功素材。不要为了推进流程把 unknown 改成成功或伪造静音替代对白。

### P2：声音停止控制仍被作为新音效提交

第一轮 `ep1-s1-l5` 的原文是“脚步声停住，短暂的安静。”。剧本生产审核已将其分类为 `control_only`，但 `StoryDelivery` 中仍为 `sfx`；第一场原生 `script.json` 仍将其置于 `sound.production_description`，该场账本记录 3 次音效提交。

源代码核对显示 `audio_audit_issues` 对 `non_acoustic` 生成问题项，对 `control_only` 没有相应强制转换或阻断。它是上游分类与下游执行之间的一处规则缺口。本轮未因该问题中断，不能将其描述为三轮失败的根因。

建议保留原文与来源定位，将控制意图单独传递给编排器；只停止对应的活动背景、保留必要停顿，不生成一段名为“停止/安静”的新声音。需要同时处理“当前并无对应背景”的情形，不能凭空补造背景或删除剧情关键声音。

### P2：故事因果解释仍需要内容审阅

第一轮具备找到钥匙、道歉及固定存放位置的结局。但对白中坚持“叠围裙的时候根本没碰钥匙”，后续直接从围裙口袋找到钥匙，没有进一步解释此前记忆为什么有误。它可以是人物误记，现有证据不能据此判为逻辑矛盾；作为成品，应补强发现线索与承认误记之间的因果表达。此次未人工改稿。

## 本机服务与 App 验证边界

测试完成后，本机 App API 8895 和 Story API 8897 的 health 均返回 HTTP 200，数据库状态核验成功。H5 5193 无法访问，浏览器返回 `ERR_CONNECTION_REFUSED`，本机 HTTP 探测也失败。因此未完成本轮 App 页面展示或播放检查。H5 不可用是独立的本机预览问题，不能据此解释之前的模型请求 ConnectError。

没有最终 AudioMix，因此本轮三份作品均无独立 PCM 成品审计、人工试听或 Android 验收。第一轮 `technical_media_audit=passed` 仅表明已下载的剧本等现有制品审计通过；`requested_outputs_available=false`，不能将其记为广播剧成功。
