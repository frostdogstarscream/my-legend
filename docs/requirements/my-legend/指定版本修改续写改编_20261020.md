# 指定版本修改、续写、改编与广播剧交付

本次修改原真实链路，独立演示副本 `servers/my-legend-prototype-copy-20261020` 保持原样。演绎制作仍暂停。

## 使用入口

打开原 App：<http://127.0.0.1:5193/>。进入已有作品详情，页面下方“基于当前版本创作”提供：

| 操作 | 行为 | 版本关系 |
|---|---|---|
| 修改剧本 | 填写要求，生成修改后的剧本并制作广播剧 | 同一作品、同一故事的新版本，原版本保留 |
| 续写下一章 | 基于当前版本写一个新章节，目标约90秒 | 原章节完整保留，新章节追加在末尾 |
| 改编故事 | 填写要求、保留元素和改变元素 | 独立作品、新故事，保留源版本关联 |

续写当前交付包含原章节和新章节的完整广播剧，约90秒是新增章节的创作目标，不是整部音频的时长保证。实测时长以播放页为准。改写前后未变的台词仍可能重新配音，音效按现有缓存机制复用；本轮没有实现跨故事版本的逐句配音缓存。

页面使用先试听策略：无需人工确认大纲，不执行剧本内容质量评审、音频可制作性语义评审和声音编排语义评审。保留输入格式、源版本归属、输出版本对应、台词素材齐全、音频解码和时间轴等执行必需检查。语义质量标为未审核，不伪造审核通过。

## 生产接口

沿用 `POST /api/v1/production-jobs`，新增 `source.kind=operation`：

```json
{
  "idempotency_key": "unique-operation-request",
  "source": {
    "kind": "operation",
    "intent": "continue",
    "source_version_id": "实际源版本ID",
    "delivery": {"kind": "StoryDelivery", "sha256": "实际哈希", "source_version_id": "实际源版本ID", "media_type": "application/json", "size_bytes": 123},
    "manifest": {"kind": "RenderManifest", "sha256": "实际哈希", "source_version_id": "实际源版本ID", "media_type": "application/json", "size_bytes": 123},
    "instruction": "在原故事之后续写第二天发生的新故事。",
    "target_duration_seconds": 90
  },
  "outputs": ["script", "audio"],
  "mode": "automatic",
  "review_policy": "listen_first",
  "sound_workflow": "sound_bridge/1",
  "audio_delivery_policy": "audio_first"
}
```

这里的 artifact 字段是示意，实际必须使用当前用户作品返回的引用，不能直接复制占位值。服务器在提交前校验源素材归属；新结果必须具有正确父版本，不能拿旧结果充当新生成。

修改时设置 `intent=revise` 并增加 `source.edit`：

```json
{"scope": "whole_story", "target": {}, "downstream_policy": "replan_affected"}
```

API 还支持 `line`、`scene`、`episode`、`arc`、`ending` 等范围，目标 ID 来自源剧本。App 首版提供自然语言整稿修改入口；本次真实测试通过 API 指定 `ending`，额外验证受保护场景不变。局部修改后是否重规划后续章节由 `downstream_policy` 决定。

改编时设置 `intent=remix` 并增加 `source.remix`：

```json
{
  "retain_elements": ["人物及关系"],
  "transform_elements": ["背景与核心物件"],
  "relation_to_source": "adaptation"
}
```

修改与续写可传原 `work_id` 归入同一作品制作记录；改编不传，建立独立作品。

## 内部调用与交付

生产 Worker 将上述请求转换为 StoryGenerate `POST /v1/plans` 的 `revise`、`continue`、`remix`，通过 `source_selector.type=by_id` 精确绑定源版本。已有自动执行策略提交大纲执行指令，不等待人工审批。

StoryGenerate 写作完成后返回新 `StoryDelivery`、`RenderManifest`；生产端检验父版本和故事身份关系后，交给现有声音桥接、真实配音、音效缓存、实测时间轴和混音流程，最终通过原播放接口回到 App。

改编创建新故事时，生产适配器会显式带入源剧本中的角色选择和演绎者绑定，避免底层默认将原角色当作未绑定的新角色。显示姓名兼容角色档案、故事角色塑造和临时配音角色三种来源。本次尚未增加在改编表单中重新挑选角色的功能。

输入重复提交沿用幂等机制。App 对相同输入的请求保留幂等键，网络失败后重试不会无意重复创建；修改输入则使用新键。
