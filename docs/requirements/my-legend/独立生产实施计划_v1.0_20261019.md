# 我的传说独立生产实施计划

版本：1.0  
日期：2026-10-19  
状态：实施中。2026-10-19 用户调整优先级：暂停视觉制作与演绎验收，先完成剧本和音频验收；演绎目标等待重新确定。下文视觉范围保留为历史计划，不作为当前执行授权或当前音频验收前置条件。详见同目录《剧本与音频优先验收_20261019.md》。  
适用范围：uni-app 客户端、StoryGenerate、声音工作流、视觉工作流、声画整合与生产后台。

目标是让用户通过 App 或业务 API 提交创作需求，后台独立生成故事剧本、广播剧和视觉表演，再整合为同一作品。生产过程依靠已部署的代码、模型 API、素材库与任务配置，不依赖开发会话逐页查看、人工补写任务文件或针对某次输出修改代码。

本计划更新 2026-10-15 产品草案中“自动视觉制作后置”的范围：能力范围内的自动视觉方案、执行和声画整合进入核心生产主线。现有 UI、已有工作流和契约继续复用，历史验收结果保留各自适用范围。

## 1 首版范围

首版支持两种入口：从创意生成作品；从已有的结构化剧本版本生成声音或演绎。用户可选择剧本、广播剧、视觉成片中的一种或多种输出。首版有声视觉成片依赖声音和实测时间轴，后台自动补齐这两个依赖。

客户端保留现有五个底栏，在作品内组织剧本、声音、演绎和生产进度。普通用户只需要创作要求、角色、时长目标、音色、视觉风格和输出类型；模型参数、素材映射、工作流 JSON 与重试细节由后台管理。

默认以自动制作模式完成私人作品。可选的审阅模式允许用户在 App 中确认大纲或提出修改意见；产品内审阅不依赖开发会话。自动制作完成不等于人工认可效果，也不触发公开分享。

视觉首版沿用现有视觉工作流与可用素材进行场景、人物和动作编排，输出 MP4。每个视觉方案必须声明素材和动作能力范围。任意复杂肢体动作、逐字口型、连续画面生成模型和手机内实时引擎，不作为当前已具备能力。关键动作超出当前范围时返回可定位的能力缺口；不能静默替换为等待或动作卡后记为完整表演成功。

基础分镜可以保留为明确选择的输出模式；正式演绎与基础分镜分别记录验收结果。新增绘制素材或图像生成能力采用独立素材模块，禁止把会话内人工生成的单个故事素材作为自动生产的隐含前提。

本节保留起始状态；后续已完成的实现和测试以第 9 节及同目录实施进度记录为准。

| 环节 | 已核对的基础 | 下一步缺口 |

| 故事生成 | StoryGenerate API、Worker、大纲确认、章节和结构化交付已接入 | 自动制作策略、统一任务衔接、后台主动同步结果 |
| 声音制作 | 音色绑定、真实逐句 TTS、音效、缓存、实测时间轴和混音已有实现 | 独立声音任务与交付、通用选声策略、跨任务成本控制和恢复 |
| 视觉工作流 | 原图包含 automatic 模式、素材目录、编排和预览；缺上下文时仍会中断 | 通用语义上下文生成、完整素材匹配、跨场角色状态与能力检查 |

| App 与媒体 | 实际 MP4 播放、角色与字幕时间轴、制作和审核入口 | 三类结果独立可用、统一任务 UI、关闭页面后全链路继续 |
| 运行与交付 | 本机服务、加密凭据、局部任务与制品记录已有实现 | 持久总任务、租约与崩溃恢复、服务配置解耦、目标设备验收 |

2026-10-19 已有 102.32 秒样例覆盖 3 场、39 个事件，包含真实模型声音和基础分镜。它作为历史集成样例保留，不计入本计划的新输入无人介入验收集。

## 3 模块划分和调用边界

首版采用模块化后端和独立 Worker。模块通过版本化协议调用，可单独测试和替换；不要求首轮全部拆成不同服务器。业务 API 使用现有 FastAPI 路线，生产任务使用独立业务表和制品目录，原工作流保留各自检查点。生产业务表计划使用现有独立 PostgreSQL 实例的新命名空间，不改写 StoryGenerate 内部表。

| 模块 | 输入 | 输出 | 完成条件 |
|---|---|---|---|
| 统一生产编排 | 创意或剧本版本、输出选择、策略、预算 | 持久生产任务、子任务、结果清单 | 请求的结果齐备，或明确结束于失败、取消、待输入 |
| 故事服务 | 创意、角色、题材、时长目标、版本上下文 | StoryDelivery、RenderManifest | 结构、引用和故事服务交付检查通过 |
| 声音服务 | 冻结剧本、声音配置、任务预算 | 分句声音、音效、混音、MeasuredTimeline | 产物有效、来源完整、实测时间一致 |
| 视觉方案服务 | 同版剧本、角色档案、场景信息、素材能力 | VisualContext、VisualPlan、能力缺口 | 人物、场景、动作、对象和结果有来源；执行能力可核验 |
| 素材服务 | 资产标识或素材需求、风格和使用范围 | 版本化素材、哈希、能力信息 | 可读取、规格匹配、同角色跨场稳定 |
| 视觉执行服务 | VisualPlan、素材包、实测时间轴 | 演出执行数据、视频或帧序列 | 按指定能力执行，输出可解码，动作与时间来源可追溯 |
| 整合服务 | 同版本声音、视觉和字幕 | 广播剧、MP4、封面、PlaybackManifest | 全事件覆盖、版本匹配、时间一致、播放制品完整 |

声音制作与视觉方案可以在结构化剧本完成后分别推进；最终视觉定时和声画合成必须等待实测声音时间轴。广播剧生成不依赖视觉成功，剧本阅读不依赖声音成功。

总任务可暴露已完成的部分结果。如果请求的视觉失败，已有广播剧继续可用，但总任务不能显示全部成功。子模块单独调用与总任务调用使用同一执行入口。

## 4 公共协议和状态

共同字段至少包括 work_id、source_version_id、job_id、stage_id、schema_version、profile_version、输入哈希、制品哈希和幂等键。原有 StoryDelivery 与 RenderManifest 继续作为来源契约，新增协议通过版本号扩展。

新增协议清单：

- ProductionRequest：创意或来源引用、输出类型、自动或审阅模式、音色策略、视觉能力配置、预算和超时。
- StageResult：子任务状态、输出制品、来源范围、质量报告、用量、错误和可恢复性。
- MeasuredTimeline：采样率、素材采样帧、事件边界和锚点；明确实测音频、固定停留和估算动作三种时间来源。
- VisualContext 和 VisualPlan：稳定人物身份、按场在场人物、场景事实、动作施动者和对象、素材绑定、简化项与能力缺口。
- PlaybackManifest：剧本、广播剧、视频、字幕和封面的同版本引用，以及各结果的就绪状态。
- RunEvidence：软件、提示词、策略和素材版本，模型调用与修复次数，人工或会话介入记录。

拟新增统一入口，具体字段在 M0 冻结：

| 接口 | 作用 |
|---|---|
| POST /api/v1/production-jobs | 从创意或冻结剧本创建总任务，返回任务 ID |
| GET /api/v1/production-jobs/{id} | 只读查询阶段、结果、用量和错误 |
| GET /api/v1/production-jobs/{id}/artifacts | 获取已就绪结果及播放引用 |
| POST /api/v1/production-jobs/{id}/cancel | 请求取消尚未完成的工作 |
| POST /api/v1/production-jobs/{id}/resume | 明确恢复失败任务或提交待补信息 |
| GET /api/v1/production-capabilities | 获取可用模块、声音、视觉方案和限制 |

故事、声音、视觉和整合模块分别提供提交、查询、结果和恢复接口。现有故事及制作 API 保留兼容层，逐步委托统一任务服务。GET 查询不再承担阶段推进或启动收费任务的职责。

总任务状态采用 queued、running、needs_input、succeeded、failed、cancelling、cancelled。进度用于展示，阶段成功以实际制品和校验结果为依据。取消请求不能保证撤回已被供应商接受的推理；保留用量和已有制品。

分开记录 execution_status、technical_quality、human_review 和 publication。automatic 模式的人工审核为 not_required 或未审阅，不能写成 approved；自动检查通过后可提供私人结果。reviewed 模式按用户选定节点等待 App 内操作。

## 5 实施里程碑

### M0 冻结生产协议与验收范围

依赖：本计划。责任模块：业务 API、适配层和验收工具。

交付：公共 Schema、状态迁移表、模块能力清单、错误分类、预算策略、自动与审阅模式定义、接口说明、旧接口迁移规则。

视觉能力清单必须来自实际目录和执行器：背景、演员数量、动作、表情、场次与单批时长限制逐项登记。素材不足和无法实现的关键动作使用明确错误，不靠默认值掩盖。原工作流依赖保持固定；扩展发布为新版本并重新锁定。

通过条件：协议样例可校验；同版引用、幂等冲突、未知能力和状态冲突有一致处理；定义新输入验收集的构造规则，但不使用保留输入调试模型。

### M1 建立后台总任务与恢复机制

依赖：M0。责任模块：生产 API、任务仓库、总 Worker 和启动配置。

交付：持久任务与子任务表、Worker 领取和租约、心跳、阶段推进、恢复、取消、制品登记、用量记录，以及旧 API 兼容接入。

先使用隔离的模块替身验证编排，再连接现有真实服务。每个外部调用先持久化意图和幂等标识；超时后优先查询供应商结果或复用登记记录，结果不明时停止并标记，不盲目重复付费。服务地址、媒体地址、依赖目录和启动命令改为部署配置，替换运行逻辑中的本机固定值。

通过条件：不打开浏览器、不轮询 API，后台也能推进；关闭客户端不影响任务；Worker 重启能恢复；两个 Worker 不重复领取同一阶段；相同请求不重复提交；取消与超时不会留下永久 running。

### M2 接通故事到广播剧的独立生产

依赖：M1。责任模块：StoryGenerate 适配、声音服务与时间轴。

交付：从创意到冻结剧本，再到真实广播剧的自动链路；独立声音任务接口；角色音色策略；表演标注校验；MeasuredTimeline 和广播剧播放结果。

自动模式采用明确记录的策略推进故事计划，不伪装用户点击批准；如上游需要新增策略身份或接口语义，发布兼容版本。审阅模式继续等待 App 内确认。音色绑定按稳定角色身份保存，未绑定时使用固定、可解释的配置策略；不能依赖当前样例的角色名字。

声音工作流保留原缓存和处理记录。生成完成可交付带质量状态的私人音频；人工意见与自动技术处理分别记录。对白、旁白、音效、环境声和动作不混为朗读文本。音乐按能力清单提供；不支持的输入显式报错。

通过条件：新角色和新剧本可独立生成广播剧；旁白路由正确；无台词丢失或重复；实测时间来自有效音频；局部重做只失效受影响制品和后续时间轴；预算用尽有明确结果。

### M3 建立通用视觉方案和素材绑定

依赖：M0、M1；接入 M2 产出的同版剧本。责任模块：视觉语义生成、素材服务和适配层。

交付：将剧本与资产能力转换为 VisualContext、VisualPlan 的程序和模型步骤；版本化角色外观与场景绑定；能力预检；语义检查与有限修复。

先从剧本提取事实，再在已发布素材与动作范围内做制作选择。模型负责方案建议，确定性代码检查身份、在场状态、对象引用、资产存在性和动作能力。外观和镜头等制作选择显式标记，剧情事实不允许自动改写。

移除统一室内背景、全角色默认在场、按序选外观及所有动作映射 wait 的通用路径。场景和人物状态按源事件传递；跨片段不重置身份、位置关系和关键物体状态。原 automatic 模式可复用，但只有必需上下文完整才进入执行。

通过条件：新场景能选择对应背景；不在场人物不会出现；同角色跨场外观一致；动作的施动者、对象和结果正确；超出能力时返回问题位置。复杂动作不能因字幕中写出动作名称而被计为执行成功。

### M4 接通视觉执行和声画整合

依赖：M2、M3。责任模块：原视觉工作流、Dart 编排、渲染器、整合与制品服务。

交付：视觉任务接口、受能力约束的执行数据、使用实测时间轴的 MP4、字幕、封面、PlaybackManifest；保留可单独播放的广播剧。

首轮选定一套正式视觉方案及素材包，覆盖已公布的背景切换、出入场、移动、朝向、等待和表情等实际支持项。修灯、递物等关键动作如进入首版成功案例，须增加对应素材和执行能力并单独验证。基础分镜模式不计入正式动作覆盖率。

长作品按引擎实际限制切段并传递状态，不能通过放宽限制或丢事件绕过门禁。声音、画面和字幕遵循同一时间轴；动作拟音对齐需使用素材实际发生点，不能默认文件起点就是动作接触点。

通过条件：请求范围内事件完整覆盖；音轨无截断；字幕与对应事件一致；跨段无累积漂移；实际动作符合 VisualPlan；同一制品清单中无混用版本。时间同步技术门槛暂按约定锚点误差不超过一个输出视频帧，视觉与听感质量另评。

### M5 将统一任务和三类结果接回 App

依赖：M1 接口可用后开始，完整验收依赖 M4。责任模块：uni-app、业务 API 和媒体访问。

交付：输出选择、自动或审阅模式、制作参数、统一进度、可恢复错误、作品结果、继续阅读收听观看、版本切换。

保持现有底栏和主要视觉设计。去掉前端承担流程推进的逻辑，页面只提交和展示后台任务。制作完成后无需逐页检查才能拿到结果。声音和视频使用后台返回的制品；链接到期可刷新，跨设备不返回 127.0.0.1 地址。

通过条件：提交后离开页面或重启 App，任务继续并能重新找到；只有剧本、剧本加广播剧、完整声画三种输出组合状态正确；部分失败不隐藏已成功结果；切换版本不串音轨或字幕。先验收 H5，再验收 Android 真机；小程序单独记录后续适配结果。

### M6 完成无人介入验收与可部署交付

依赖：M2 至 M5 的功能完成。责任模块：独立运行工具、测试、部署配置和文档。

交付：API 驱动的验收脚本、冻结版本清单、新输入运行记录、质量报告、启动与恢复说明、配置模板和部署依赖清单。开发测试可以使用模块替身；真实模型运行另行记录，不能以替身通过代替。

先做一个预算受限的新输入真实试跑，然后运行保留验收集。执行期间固定代码、提示词、配置和资产，只允许程序预先实现的有限修复。遇到问题保留失败，修复后开始新版本的新一轮，不覆盖原记录。

通过条件：满足第 7 节全部运行要求，提交三类实际制品和完整证据。发布到可供手机访问的测试环境时，完成真实身份与作品归属检查、服务端凭据配置、媒体权限和 Android 真机验收；本机 H5 结果不替代此门槛。

## 6 开发顺序和第一批任务

主顺序为 M0 → M1 → M2 → M3 → M4 → M5 → M6。M3 的协议、素材目录整理与 M2 可并行开展；M5 的客户端接入在 M1 接口稳定后推进。这里描述任务依赖，不默认新增人员或子代理。

第一批实施锁定为 M0 和 M1：

| 任务 | 具体内容 | 交付检查 |
|---|---|---|
| T01 | 定义 ProductionRequest、StageResult、RunEvidence 和状态机 | Schema、正反例、状态迁移说明 |
| T02 | 建立总任务、子任务、调用意图、制品、用量和事件记录 | 独立命名空间迁移、升级及恢复验证 |
| T03 | 实现总 Worker 的领取、租约、心跳和阶段推进 | 关闭客户端、进程重启和并发领取测试 |
| T04 | 建立模块客户端接口，接入故事查询与制品导入 | 后台主动同步，GET 无启动副作用 |
| T05 | 增加总任务提交、查询、结果、取消和恢复 API | 幂等、预算、错误、部分结果契约测试 |
| T06 | 提供无浏览器执行的编排验证命令 | 隔离替身完整链路；清楚标记模型调用为零 |

第二批为真实故事与广播剧，第三批为视觉方案与执行，第四批为 App 整合、保留集和真机验收。每批以通过条件结束；当前不承诺未经实现和模型稳定性验证的日历工期。M1 完成后根据真实耗时与外部能力重新估算后续排期。

## 7 无会话介入验收

### 7.1 冻结和留证

运行前保存代码版本或源码清单哈希、依赖锁、提示词哈希、模型与供应商配置标识、素材版本、预算、超时和自动修复上限。模型凭据不进入证据包。

自动修复必须在运行前声明：适用错误、最大次数、影响范围、是否会产生额外模型调用。初始默认建议为每阶段最多 1 次语义或结构修复，并受总调用和费用上限约束；确切规则在 M0 固定。外部提交结果不明的请求不能作为普通重试。

2026-10-19 诊断更新：前八轮新创意试跑保持其原有每阶段 1 次修复策略不变。第八轮大纲消耗该额度后，正文所需修复被共享预算拒绝。后续新冻结诊断请求改为每阶段最多 2 次共享修复，整轮仍为 80 次供应商调用、1800 秒；这是新请求的显式配置，不改历史记录或 App 默认值。正文、大纲、结构和标注修复仍共用故事阶段额度。用户此前授权真实试跑不设金额上限，费用仍按实际账本披露；正式保留集使用的策略必须在运行前固定。

每次运行记录 session_interventions、manual_artifact_edits、out_of_band_context_injections、policy_repairs 和 provider_calls。人工在开发会话中补写上下文、替换文件、改提示词或修代码，都使本次独立运行不通过。预算只记录已知用量；供应商费用未知时标为未知，不虚构金额。

### 7.2 验收集

保留 6 个未针对性调试的新创作输入，覆盖多角色对白、旁白和音效、室内外切换、人物出入场、跨片段连续性，以及同角色跨场景声音与外观一致性。每个成功案例只使用公布支持的视觉能力，首轮目标时长采用现有 StoryGenerate 接口支持的 90 秒；现有接口的目标时长枚举为 90、120、150、180、300 秒。目标时长不当作实测结果，超长按策略处理，不能截断结局；视觉执行按引擎限制切段。

另设隔离的异常用例：重复提交、进程重启、网络超时且结果不明、预算耗尽、缺少资产、不支持的关键动作、来源版本变化和取消。异常用例的通过标准是正确保留或终止任务，不伪造产物、不重复付费、不假报成功。

实际模型验收开始前，按单案例测量填写整批调用上限、费用上限和最大运行时间；计划阶段不发起收费测试。成功率报告包含全部尝试和失败，不能筛选成功样例后重新计算。

### 7.3 通过标准

| 维度 | 首轮标准 |
|---|---|
| 独立运行 | 6 个支持范围内的保留案例均从 API 提交到请求结果齐备；每次会话介入、手改制品、临时上下文注入均为 0 |
| 自动修复 | 全部发生在冻结策略内，次数及额外调用可追溯 |
| 后台推进 | 无客户端轮询也可完成；至少一个运行覆盖 Worker 重启恢复 |
| 来源与版本 | 全事件可追溯，无遗漏重复，剧本、声音、视觉、字幕引用同版 |
| 真实媒体 | 实际模型配音和音效存在，视频可解码播放，时间基于实际媒体 |
| 视觉执行 | 每个要求执行的动作有对应执行或可核验结果；动作卡不冒充完整动作 |
| 失败与成本 | 异常用例按预期停止或恢复，不超配置上限，不盲目重复提交 |
| 产品操作 | 用户正常选择、查看、可选审阅都在 App 内完成 |
| 人工效果评价 | 在冻结运行结束后独立评估故事、声音、画面和同步；不回写修改该次结果 |
| 终端 | H5 和 Android 真机分别留结果；小程序未测时不标为通过 |

6 个案例通过只代表首轮小样本验收，不代表任意故事都能成功。自动完成率、自动修复率、耗时、调用量和人工效果评价分别报告。任何失败都保留原始运行；修复后的验收增加新记录。

## 8 依赖和处理规则

| 依赖或风险 | 处理方式 |
|---|---|
| 原工作流要求用户批准 | 区分自动制作策略与用户批准；必要时升级契约，禁止伪造人工身份恢复 |
| 新剧本缺少必要动作对象或关键事实 | 在故事交付前补齐；无法确定时返回 needs_input，不由视觉模块擅自决定剧情 |
| 视觉素材或执行能力不足 | 返回具体缺口；增加资产与执行支持后发布新能力版本 |
| 分段导致角色状态丢失 | 使用同源身份与状态传递；建立跨片段连续性校验 |
| 外部请求超时 | 记录提交意图和外部任务号；查询或对账后恢复，未知状态不盲重发 |
| 费用和时长失控 | 全任务及各阶段预算、并发和截止时间；已成功素材优先复用 |
| 本机实现不能直接供手机访问 | 配置化服务地址与媒体地址，准备测试环境、身份与作品隔离，再做真机验收 |

首版暂不扩展会员支付、商城交易、NFC、社区、角色聊天和多人协作。它们可保留原需求记录，不占用本次独立生产主线。
