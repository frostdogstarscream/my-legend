## 生产调用顺序

对不含 visual 的请求，生产注册器为 AudioStage 注入 AudioPlanner。冻结剧本完成后，音频阶段先进行独立模型编排、逐行独立复核；只有方案和复核都通过，才预约素材生成预算、调用 TTS/SFX。之后汇总各场真实素材，在全剧范围执行编排，交付混音与 measured_timeline/1.1。含 visual 的旧路径继续保留原逻辑，本次不运行。

编排模型使用独立 AudioModel 客户端，复用用户已配置的故事模型端点与凭据，不依赖视觉模块。启动器从受保护的既有模型配置注入 Worker 专用 MY_LEGEND_AUDIO_MODEL_BASE_URL、MY_LEGEND_AUDIO_MODEL_KEY、MY_LEGEND_AUDIO_MODEL_ID；不把 Key 写入制品。媒体子进程环境移除 AUDIO_MODEL_KEY，音频供应商配置仍由原受保护启动方式加载。

每次模型计划或复核请求经 StageContext.effect 先持久登记，计入总调用预算，并受阶段截止时间和取消检查控制。网络/结果不明不会作为语义修复重试；已完成响应在 Worker 重放时复用。max_repairs_per_stage 同时限制计划/复核修复轮数，不能分别获得无限重试。复核格式或引用错误只重做复核；真实语义缺陷要求重做方案后再次独立复核。

提示版本为 audio_arrangement_planner/1.0 和 audio_arrangement_review/1.0，明确输入文字是数据，不是运行指令。模型只选择声音模式、锚点、增益、衰减和淡出，不能改写剧本。动态 Schema 给出准确源行数；复核逐行绑定来源 ID、完整文本和方案规范化字节哈希。成功登记 AudioArrangement、AudioArrangementReview、AudioArrangementEvidence；失败登记 AudioArrangementIssueReport 并阻止声音生成。自动语义通过不等于人工听审。

## 素材与编译

适配器新增 audio_marker 路由，只允许 action、无素材引用及无场内时间关系，映射为 duration_ms=0 的原生 action。这里的局部标记不负责最终定时，正式位置由全剧 AudioArrangement 决定。背景 sfx 映射为 ambience，仍由原 SFX 模型生成；对白/旁白保留原音色与表演指令。

仅含非音频标记的场景不启动原生声音任务，结果记 not_required，不伪造 native technical_passed。原文行仍完整进入最终时间轴。所有有声音的场景读取原生预览 assets.json，核对技术结果、映射和素材目录边界，再交给全剧编译器；不拼接各场 draft.wav。

每次本地编译使用新的 compilations 目录。已存在同任务最终输出只有字节一致才能重用，发生差异明确失败，防止恢复时覆盖不同结果。最终 AudioStage 校验新时间轴版本、方案哈希、剧本覆盖、音频 WAV 帧数及编译报告绑定，登记 AudioCompileReport。生产返回旧版时间轴时不静默降级。

输入冻结包含方案哈希与指令上限。AudioCache 继续保留原生原始片段，局部重制按既有源版本及候选修订复用；编排改变不直接绕过供应商缓存键。背景声结束位置跟随重新测量后的对白时长重算，旧作品保持不变。
