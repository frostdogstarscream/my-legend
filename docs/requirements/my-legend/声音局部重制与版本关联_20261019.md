# 声音局部重制与版本关联

范围：同一冻结剧本内重新生成指定对白、旁白、音效，或更换角色音色。创建新的生产任务；原剧本、原广播剧、原视频和历史制作记录不覆盖。修改剧情文本仍应通过故事服务产生新的 StoryDelivery，本接口不改写剧本。

## 接口

`POST /api/v1/production-jobs/{job_id}/remake-audio`

输入：

```json
{
  "expected_revision": 1,
  "idempotency_key": "app-audio-remake-unique",
  "regenerate": [
    {"episode_id": "episode-1", "scene_id": "scene-1", "line_id": "line-1"}
  ],
  "outputs": ["audio"],
  "budget": {"max_provider_calls": 80, "max_elapsed_seconds": 1800, "max_repairs_per_stage": 1}
}
```

`voices` 可选，提供时必须是完整且合法的角色/旁白音色绑定；未提供时继承来源作品的 VoiceBindings。`regenerate` 可以为空，但必须确有音色变更。可选择 `outputs: ["visual"]`，其依赖会重新生成声音时间轴并制作视频。

服务端核对作品归属、任务版本、终态和未结算调用。来源必须已有 StoryDelivery、RenderManifest、AudioMix、VoiceBindings、AudioCache。动作停留不能通过声音重制接口当作生成声音。相同幂等键和相同输入返回同一个新任务，改变输入而复用幂等键会被拒绝。

## 缓存与调用

原声音流程完成后新增不可变 AudioCache ZIP 制品。它包含已成功的原始声音、原生请求指纹、来源剧本和清单哈希、当前逐事件候选版本。缓存不包含凭据、下载签名 URL、调用账本或工作流检查点。

新任务在独立目录导入成功缓存。原始音频工作流根据实际请求内容决定命中：音色、模型、文本、有效表演指令或候选版本改变时重新生成。指定重做的事件使用该新任务独有且可重放的候选标识；没有选中的事件保留上次候选，避免第二次局部重制退回第一次修改前的声音。

导入不会覆盖目标目录中 running、unknown 或 failed 的原生任务。来源绑定、文件哈希或 ZIP 路径不合法时拒绝复用。未知外部提交仍需核实，不通过创建缓存条目伪装成功。

实际新增调用从新任务的原生调用账本计算；导入历史缓存不计为新调用。当前阶段预算仍按所有可能需要生成的声音预留保守上限，最终记录实际新增次数；因此“只重制一段”不代表可将整任务预算无条件设置为 1。供应商金额费用仍未核实。

## 失效与历史保留

| 内容 | 新重制任务的处理 |
|---|---|
| StoryDelivery、RenderManifest | 引用同一冻结版本，不请求模型重写故事 |
| 未改变的原始声音 | 按原生实际请求指纹复用 |
| 选定事件或变更音色影响的声音 | 重新生成，保留新调用记录 |
| 后处理音频、广播剧混音 | 从原始声音重新处理并合成 |
| MeasuredTimeline | 按新媒体实测帧数重建，后续事件重新定时 |
| 视觉执行、视频、字幕、封面 | 新任务不复制旧结果；选择 visual 时重新制作 |
| 旧任务和旧媒体 | 完整保留，仍通过原任务播放入口访问 |

剧本 source_version_id 可以相同；制作结果版本由新的 job_id、媒体哈希和 PlaybackManifest 区分。不能把旧视频配上新音频后继续使用旧字幕或旧时间轴。

## App

作品处于终态、具备声音、AudioCache 和 VoiceBindings 且无未结算调用时，剧本对白、旁白、音效旁显示“重做这段声音”。用户可多选，查看重制数量，再提交；可选择同时重做像素演绎。提交使用持久幂等键并打开新制作记录。

App 已加入“更换角色或旁白音色”。打开后读取当前作品的音色绑定和服务端目录，核对来源版本，逐角色显示原音色、可选音色与受影响的配音段数。更换一个角色时提交完整绑定，保留未改变的角色和旁白；也可与指定片段重制一起提交。目录不再支持的旧音色要求明确重选，不自动替换。加载失败、来源缺失或绑定不完整时阻止提交。网络失败后同一选择继续使用原幂等键；改变选择生成新的请求指纹。

历史声音任务如果没有 AudioCache，界面不显示局部重制入口，接口返回 AUDIO_REMAKE_CACHE_UNAVAILABLE。不会猜测或篡改旧缓存；需要通过后续明确迁移或重新制作获得符合该协议的缓存。

## 验证范围

- PostgreSQL 隔离测试验证归属、幂等、旧任务不变、未知结果阻断、语音缓存所有权、仅导入已有剧本及新任务不复制视频。
- 原始音频工作流实测使用合成适配器并禁止网络：单段重制仅增加一次适配器生成，新的时长回写混音和时间轴；再次重做另一段保留第一次候选。独立专用音频环境 2 项测试通过。
- 隔离 H5 测试验证选中一段声音、显示重制范围、提交精确 episode/scene/line 和版本、跳转新任务。证据位于 `runtime/my-legend-production/ui-remake-20261019/`。
- 新增 5 项音色选择纯函数测试，前端合计 53 项通过。隔离浏览器实际选择角色新音色，保留旁白，首次提交返回模拟 503 后重试使用相同幂等键并跳转新任务；仅产生两次测试 API 请求，无真实模型或正式数据库访问。证据位于 `runtime/my-legend-production/ui-voice-revision-20261019/`。最终自定义事件修正后已再次验证选择与提交面板保持一致，类型检查、H5 和 App 平台资源构建通过。
- 上述局部重制测试未调用真实模型。原生缓存与媒体链路通过不代表供应商效果、真实音色重制听感或 Android 验收完成；真实独立首轮试跑另行记录。
