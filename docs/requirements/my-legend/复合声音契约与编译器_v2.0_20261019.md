# 复合声音契约与编译器 v2.0

状态：离线契约、确定性编译器与媒体回归已实现，未启用到真实生产 Worker。视觉继续暂停。本文不代表真实模型生成、App 播放或人工听感验收完成。

## 证据和目标

第七轮真实音频诊断的三次规划都为两条复合声音重复了来源：原剧本 27 行，规划结果 29 行。原文一行包含背景变弱及滴水出现，另一行包含滴水消失及鸟鸣出现。把这些操作强行压成一个模式会遗漏声音，把来源复制成两行又破坏准确来源绑定。

本扩展保留唯一原文行，在其 operations 中表达多个具体操作。每个操作有全计划唯一的 operation_id、逐字 cue_text、reason、锚点和必要控制字段。cue_text 必须是本源行的非空原文片段，用作该素材的声音依据；不能把整条包含多种声音的描述重复送给每个素材生成器。完整原文仍保留在父事件 text 中。

对白、旁白只能有一个 speech 操作，cue_text 必须等于完整原文，角色身份不变。非朗读 action 不能凭空生成新声音，仍仅允许动作注记和背景控制；普通 sfx/music 不允许以 action_note 隐去声音。

## 方案和锚点

方案版本为 audio_arrangement/2.0，模型类 CompoundArrangement。父 events 逐条、逐字、按顺序绑定 StoryDelivery，来源不重不漏。一个源行允许 1–16 个操作，全方案最多 1000 个操作，这是执行资源保护，不是剧本字数或 TTS 指令限制。

例如“雨声渐弱，檐下滴水声响起”由两个操作表示：

| 操作 | 原文依据 | 执行内容 |
| --- | --- | --- |
| fade_rain / change_background | 雨声渐弱 | 引用此前 rain 背景，在给定起止锚点之间改变增益 |
| drips / background | 檐下滴水声响起 | 建立独立滴水素材，持续至明确结束锚点 |

锚点使用 operation_id、point=start/end、offset_ms；只有作品起点的 operation_id=null。控制对象也是具体背景 operation_id，不再把多操作源行当成单个声音。背景必须有 end；一次音效、对白及控制的 end=null。一次音效和对白的结束由真实素材测量确定，控制的结束帧等于开始帧，音量变化完成位置另记 transition_end。

控制只能指向已在源顺序/行内操作顺序中建立的背景。跨源行或同一源行内的锚点均需经过依赖环检查，不能引用未知操作或让对白等待自己。重复来源、重复操作、对白截断、伪造原文依据、来源类型不符、控制目标错误均在生成前拒绝。增益变化范围和停止位置在取得实测素材后再次校验。

完整字面依据不自动证明声音理解正确。模型仍需要独立检查复合描述是否完整覆盖、声音对象是否正确、是否误把降低雨声当成生成滴水；该模型接入尚待实现。

## 时间轴和编译

新时间轴为 measured_timeline/2.0，模型类 CompoundTimeline。父事件保留原始 source/kind/text/identity_id，子 operations 记录独立实测帧数、音频哈希、处理来源、控制目标、变化范围和增益。控制不能声明具有音频，音频不能冒充控制，停止必须与目标背景的实际结束帧相同。绑定函数核对方案哈希、源版本、所有源行、操作顺序、模式、原文依据、目标及目标增益。

compile_compound 以 operation_id 接收真实素材。它将经过来源验证的方案转换为内部原子操作，复用已有循环、裁切、淡出、增益包络、对白衰减和峰值保护实现；内部键是操作 ID，绝不构造或改写一份假 StoryDelivery。公开交付仍使用原始方案 2.0 和源行分组时间轴 2.0。

内部原子文件位于新输出目录的 operations/，仅供追踪渲染；其操作键不能作为原剧本来源发布。根目录 arrangement.json 保留原始 2.0 方案，timeline.json 保留原始源行，mix.wav 为成品，compile-report.json 记录操作到来源映射、素材处理来源、内部报告哈希与内部渲染目录。素材路径相对于报告指定的内部目录解释。输出目录必须新建，禁止覆盖已有成品。

编译器不调用模型。没有素材的控制不占生成量；语音不裁切、不拉伸。更换一个语音素材的实测长度后，依赖它的背景结束、变化区间和后续声音按锚点重新计算。

## 后续接入进展：音频子进程及缓存

已接入 prepare_audio 的操作展开层，保留原始适配 sidecar 作为模板来源，以 operation-map.json 记录真正生成的原生块。每个操作都有独立块 ID，非朗读音频只使用其逐字 cue_text；控制为零时长 action，不生成素材。audio_job 已能读取 2.0，按操作汇总原生素材并调用 compile_compound。

作品缓存候选已细化到操作级，缓存 2.0 要求同一编排哈希，可按源行选择全部声音或内部 operation_id 选择单个声音。原生子进程测试验证 5 次初始生成、同任务重放零新增、单操作重制只新增 1 次；另验证跨作品音效库可复用 2 个音效。上述均为隔离替身/本地证据。公开重制 API 的操作选择、旧方案引用冻结、规划/复核、AudioStage 2.0 验证、App 与独立审计仍待接入，不能宣称整条新链路已可运行。
