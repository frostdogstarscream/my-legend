## 发现并修复的阻断问题

第一次修改流程 `9697452c-9c37-4fd3-b334-fad8820c1a1f` 的 API 技术状态为 succeeded，但正文逐行与首次作品相同。新大纲已正确包含修改要求，真实 `storycraft_episode_writer` 响应仍复制旧正文；快速交付策略未执行语义审核，也没有正文不变保护，因此继续生成了声音。该版本在本次**内容修改验收中失败**，不能因音轨或版本 ID 改变就算修改成功。原记录未重写。

本次修复：

- 明确修改任务必须把要求落实到正文，原作仅作为待修改素材，不能只更改摘要、标题或表演注释。
- 对修改稿和来源稿逐行比较类别、说话角色、正文，忽略空白差异。完全不变时在表演注释与配音前，允许一次受现有预算约束的修复；仍不变返回 `STORY_REVISION_UNCHANGED`，停止后续调用。
- 正式接收故事结果时再做一次正文不变检查，避免仅靠新版本号放行；前端提供可理解的停止原因。
- 该检查只证明正文发生变化，不替代任意修改要求的完整语义审查。本轮具体修改要求另有逐句核验。

相关实现：`production/revision_guard.py`、`production/story_guard.py`、`production/story.py`；前端错误提示位于 `src/utils/production.ts`。新增与既有故事桥接回归共 **15 项通过**，报告 `runtime/my-legend-story/tests-live-flow-revision-guard.xml`；前端 `npm run type-check` 通过。无活动制作任务时核实进程身份后，仅重启故事及声音 Worker，舞台与协调器继续运行。
