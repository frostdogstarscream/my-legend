# 声音分类回退修复与真实复测

## 完成内容

问题来源：上一轮《错放的钥匙》的开场“翻找抽屉的轻微碰撞声，突然停止”被判为 control_only；独立审核虽指出缺声，但固定 schema 禁止补声，后一次审核又放行。

本轮实现：

1. 明确区分“先发声后停止”和“停止已建立的声音”，去掉不考虑上下文的纯控制示例。
2. 审核确认 control_only 行存在 missing_sound_component 后，下一次预算内修复先重新分类，再重建声音选择 schema。重分类仍拒绝补声则失败，不允许靠后续审核改口通过。
3. 记录 validated blocking_findings，传给后续审核，并由程序核对。已被否决的执行方案不能仅修改理由或操作 ID 就通过；缺声证据必须被实际 one_shot/background 的 cue_text 覆盖。
4. 原始分类保存为 SoundSourceClassificationDraft，最终发布 SoundSourceClassification；修正时记录原始哈希与分类修订历史，不覆盖不可变工件。
5. 配音消费端再次核验问题记录与实际方案；未解决的问题不能进入音频生成。
6. 分类修复与编排修复共享现有修复预算；重放使用持久化调用结果，不重复提交已有调用。修复耗尽输出失败与诊断报告。

涉及文件：production/sound_bridge.py、production/audio_simple.py、production/repository.py，以及 tests/test_sound_bridge.py。
