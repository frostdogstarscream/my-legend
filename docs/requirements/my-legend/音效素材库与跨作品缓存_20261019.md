# 音效素材库与跨作品缓存

用户要求：每次生成音效后放入数据库缓存，便于后续复用。本能力纳入当前剧本与广播剧主线，视觉仍暂停。

## 已实现范围

以 SQLite 保存索引和追溯信息，以哈希命名的独立 WAV 保存音频。原生音效适配器完成一次真实生成后，包装层检查音频可解码、非空、采样率/声道符合请求、PCM 有限且不全静音，再保存为待听审候选。接口凭据、请求头和完整供应商配置不进入素材库。

相同用户范围内，不同作品可以查找和复用完全匹配的音效。命中时复制原始音频到当前任务，由当前任务继续完成独立处理、混音和校验；缓存不是最终混音文件，不把某部作品的音量包络或对白衰减带入另一部作品。TTS 配音不进入此音效库。

缓存命中返回 origin=sound_library 和 library_reference，原生任务账本不新增供应商请求。命中结果不携带旧供应商 usage 来冒充本轮费用。正常生成仍使用原有供应商预算与未知结果处理；缓存存储失败不会抹去已生成的音频或触发自动重新付费。

## 数据和匹配

| 数据表 | 内容 |
| --- | --- |
| assets | 文件 SHA-256、大小、采样帧数、采样率、声道和峰值 |
| entries | 请求指纹、模型/端点/最终提示词/种子/音频格式/候选版本/协议版本、审核状态 |
| origins | 每次入库的来源任务和原生 raw 任务 ID；相同文件可有多个来源 |
| review_events | 状态变化、操作人、说明和时间；重新入库不能覆盖既有否决 |

匹配键包含用户范围、供应商端点、模型、最终音效提示词、种子、采样率、声道、格式、candidate_version 和 request_revision。完全匹配才自动复用，不通过关键词或相似度把“室内滴水”“窗外大雨”等不同效果互换。换模型、参数、候选版本或用户范围均不命中。后续如供应商在同一模型 ID 下升级，可调整 request_revision 使旧缓存失效。

每个用户的目录由 owner_id 的哈希隔离。当前计划中的运行路径为生产根目录下 sound-library/<owner-hash>/index.sqlite 和 blobs/<audio-sha256>.wav。本机服务仍使用现有开发者身份，不能把这个实现表述为已完成正式多用户账号体系。

审核状态为 pending/approved/rejected。入库默认为 pending；代码支持只查已审核素材或允许未听审候选。当前自动制作请求配置 allow_unreviewed=true，只复用通过原始音频技术检查的精确候选，同时在制品中保留 pending 状态，不伪造人工批准。人工否决后的条目即使再次入库也不恢复为可用。试听管理页面尚未实现。

## 历史、重制与保护

- 文件按内容寻址，已有文件不能覆盖；入库并发使用数据库事务，保留多个来源，损坏文件不返回为可用候选。
- 人工指定重做会改变 candidate_version，从而绕过旧请求的音效缓存；相同重制任务重放仍使用其稳定候选版本。
- 作品的 raw-cache.zip 保留其独立作用。音效库命中的原始素材也可打入作品缓存，携带库引用，后续局部重制不依赖共享库一直在线。
- 复合声音的作品缓存升级为 audio_raw_cache/2.0，绑定编排哈希，候选键包含源行和 operation_id。同一源行的不同音效可以单独重做，控制操作不能冒充音频生成任务。
- 并发发布相同音频只生成一份文件/条目并保留各个来源；跨进程同时发生首次未命中时，尚未合并供应商生成请求，因此不能宣称全局并发只付费一次。各任务自己的账本、预算和未知结果规则继续有效。
