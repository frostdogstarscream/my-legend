# 编排时间轴契约 v1.1

## 目的与当前状态

新格式 `measured_timeline/1.1` 用于纯音频编排，将真实音频区间和非音频标记分开。旧 `measured_timeline/1.0` 的格式、解析及正时长要求保持不变，历史制品不改写。

本轮已实现 Python 契约、JSON Schema、版本读取、播放清单绑定及下载审计。生成端 `audio_job.combine` 仍输出 1.0；声音编排模型与新格式生产输出尚未接入。本文件不是完整混音功能已上线的声明。

## 音频事件

`duration_basis=measured_audio`，kind 为 dialogue/narration/sfx/music；必须有正时长、实测处理素材 SHA-256，不能把动作标为实测音频。`render_role` 区分 speech、one_shot 和 background，对白与旁白必须为 speech。

处理类型为 unchanged、looped_background 或 cropped_background。循环/裁切仅允许 background，且必须保留 parent_audio_sha256；对白不能通过该字段被裁切或循环。该类型表示背景素材适配到明确编排区间，不等于允许裁掉剧情。语义规划和处理范围仍需在后续编排方案中审核。

同一作品的对白与旁白必须按源顺序播放且不重叠。背景可与对白重叠。未来若需要抢话、重叠对白，应另行定义支持能力，不能静默改变本版本规则。

## 非音频标记

`duration_basis=non_audio_marker`，kind 必须为 action；start_frame=end_frame，可位于第 0 帧或成品结束帧。source_audio_sha256 必须为空，不能伪造静默文件的哈希冒充控制执行。

- action_note：保留未朗读的来源动作说明及其位置，不声称动作已被视觉执行，也不额外插入静默。
- stop_sound：target 必须指向同版本时间轴中的 background 音频事件，目标结束帧必须等于标记位置；目标不存在、指向对白、时间不一致或重复停止同一目标均拒绝。

所有源事件仍按来源序列保存，场号、行号、kind 和原文不得遗漏或改写。标记不作为当前朗读台词；现有 App 台词选择已限定 dialogue/narration 和半开时间区间，因此不会显示零时长动作。

## 方案与制品绑定

1.1 必须声明 arrangement_sha256，播放与下载审计要求同一任务注册 AudioArrangement 制品，媒体类型为 application/json，来源版本和哈希均匹配。缺少、替换或版本错配会拒绝展示为有效声音结果。

这项绑定证明“时间轴引用了哪份方案”，不单独证明方案内容或语义正确。方案模型、方案 Schema、编译器和生产端对方案内容的校验将在后续接入，不能仅凭一个匹配哈希认定计划已执行。

播放清单仍为 production_playback_manifest/1.0，其音频地址、采样率、总帧数和时长语义不变。下载审计同时核对真实 WAV 帧数和全事件原文；旧作品继续用 1.0 校验。

旧视觉渲染与合成入口显式拒绝 1.1，返回 VISUAL_TIMELINE_VERSION_UNSUPPORTED，避免暂停中的视觉消费者误读控制标记。没有启动视觉任务或修改视觉表现能力。
