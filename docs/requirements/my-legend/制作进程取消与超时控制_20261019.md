# 制作进程取消与超时控制

范围：当前 Windows 本机部署中的独立配音、Dart 编排和 FFmpeg 整合。版本：进程树控制第一版。此文档不代表外部供应商支持撤销已受理推理，也不代表 Linux 部署已经验证。

## 生命周期

生产 Worker 先建立 Windows Job Object，配置 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE，然后启动等待输入的引导进程。引导进程加入该对象成功后，Worker 才通过 stdin 发送制作命令和必要输入。隔离失败时不会启动实际制作命令，命令不经 shell 拼接执行。

配音、Dart 与 FFmpeg 的后代进程随所属作业统一管理。正常返回、取消、超时、租约丢失或控制检查失败都会关闭作业对象。Worker 被强制终止时，操作系统关闭它持有的句柄，后代进程也随之退出。不会扫描并终止机器上的同名进程。

依据：[Microsoft Windows Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。实际行为另外通过本项目真实进程测试验证。

## 控制信号

- 约每 200ms 检查本地取消标记与本次运行截止时间。
- 最多每秒读取一次任务数据库，检查取消、任务总截止时间、阶段状态、租约 token 及租约是否有效。
- 数据库控制查询不可用时停止当前本机子进程，不在失去任务控制的情况下继续制作。
- 视觉编排各批均受上述控制，帧采样期间也检查任务状态。

计时频率是轮询配置，不是对操作系统调度或远程供应商取消延迟的承诺。已被供应商受理的请求可能仍执行并计费，本机停止不等于远程撤销。

## 调用记录与恢复

配音被强制中断后，从原生 SQLite 调用账本读取已预留提交数量，保留累计用量，并将结果未确认的调用标记为 unknown。缺失结果文件不能当作零调用。任务恢复接口拒绝含 unknown 调用的重提。

任务结果增加 unknown_calls 数量。App 即使看到的是 DEADLINE_EXCEEDED，也会在 unknown_calls 大于零时提示先对账，并隐藏普通恢复按钮。unsettled_calls 仍表示全部未结算调用，不能与结果不明数量混淆。

这一步实现了阻止盲目重提与保存证据。供应商查询、结果对账及有证据的状态解除仍需要后续独立实现，不能由用户随意点击“恢复”绕过。

## 凭据范围

媒体引导进程过滤故事模型、视觉模型、数据库和服务 token 等环境变量。独立音频启动脚本按原流程读取本机加密音频配置，仅向音频子进程注入所需凭据。Dart 和离线渲染无需模型凭据。

## 验证

- 真实进程测试覆盖取消、截止时间、租约丢失、正常结束后的残留子进程清理，以及 Worker 被终止后的后代退出。
- 子进程归属建立失败时，制作命令不会执行。
- 中文、多行与包含 shell 特殊字符的输入按原始数据传递。
- PostgreSQL 测试覆盖取消、截止时间和租约过期的运行检查。
- 中断配音测试保留已知调用数量，结果未知时无法恢复重提。
- 完整后端回归 201 项通过；最后加入 unknown_calls 展示字段和环境过滤用例后，相关专项 35 项通过。两份报告分别保存在 runtime/my-legend-story/tests-production.xml 与 tests-production-process-control.xml。
- 前端 44 项测试及 TypeScript 检查通过，H5 构建通过。实际设备上的取消交互尚待验收。

所有本轮测试均使用隔离数据库、测试创建的本机进程、模型替身或合成媒体，新增模型调用为零。实现明确拒绝尚未支持的平台，不会退回只杀父进程后声称已经清理完整进程树。
