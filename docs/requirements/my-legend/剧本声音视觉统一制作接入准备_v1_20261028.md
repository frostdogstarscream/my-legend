## 首版交付目标

同一作品中，从冻结剧本开始，经声音准备、真实音频生成、视觉方案生成、实测时间绑定与人工校正，交付可保存和恢复的 H5 演绎版本。复用固定男女指挥官、31 套服装、15 套场景、基础动作、眼嘴轨道及 12 套场景主要座位。

首版以 H5 为交付终点。MP4 导出、音素口型、新增精细动作和移动真机验收分别列为后续事项。尚未实现的动作必须显示缺口，不能用待机或省略冒充完成。

## 关键困难及处理原则

### 1. 剧情动作不一定有可执行时长

timeline.py 的 NonAudioMarker 允许 action 的 start_frame 与 end_frame 相同；声音控制操作也可能是零时长。动作时间点不能直接视为行走、坐下或换景的可用区间。背景音乐和音效也可能重叠，不能套用旧串行事件假设。

方案：视觉规划先使用源事件 ID 和相对关系，如“本句开始”“下句之前”“与对白同时”；音频完成后再绑定采样帧。编译器检查行走、到达、坐姿和下一句之间是否有足够空间。允许与对白并行的动作必须有语义依据。不能容纳的动作列为时间冲突，交由修改编排或显式创建新的声音安排版本解决；不拉伸原配音，不凭空插入停顿，不静默裁掉动作。

验收包含零时长动作、重叠背景音、跨场对白、连续走坐、无可用间隙和反向定位。

### 2. AI 方案与真实素材能力必须一致

建立固定到哈希的能力快照：演员、服装、可用面部状态、动作时长、场景、实际物件 ID、坐点、路径与最多三位视觉演员的约束。模型只输出已有资源引用及有源文依据的动作；解释性选景与服装选择标为制作选择。纯动作角色、画外音和超过三人的场次也要明确处理，不能只按前三个说话角色自动选角后宣称完整。

复用既有独立模型审查，再以现有编译器进行确定性校验。修复次数有界；无法解决时报告具体源行、能力缺口和可编辑项。当前无足够证据估计任意剧本自动编排成功率，需真实样本验证。

### 3. 编辑、审核与不可变制品需要不同生命周期

建议独立记录可追加的视觉修订：作品/任务归属、父修订、来源制品引用、方案和预览哈希、创建者、问题清单。以预期修订号控制并发，拒绝覆盖别人已保存的更改。

后台初稿与人工修订分开保存；选定修订后，由提交阶段将该哈希写成正式交付制品。已完成的旧任务不重新打开并覆盖，后续调整形成新的交付修订。最终数据库结构和接口需在第一批实现中固定，并做迁移兼容测试。

机器编译通过、编辑器确认、用户观感验收分别保存。现有 confirmed/confirmed_with_omissions 不能自动转成人工验收通过。审核绑定具体剧本、音频、时间轴、视觉修订和素材哈希；修改后原审核留在原版本。

### 4. 局部修改必须正确使下游失效

| 改动 | 首版处理 |
| --- | --- |
| 表情、服装、站位、选景 | 新增视觉修订，重新校验与编译，复用音频 |
| 音色、配音或混音时间变化 | 新音频和时间轴版本，重新绑定视觉；旧帧区间不得原样套用 |
| 台词、场次或动作原文变化 | 新剧本版本，重新检查声音及视觉依赖；首版不承诺自动精细差量复用 |
| 素材目录更新 | 当前作品保持原哈希；主动升级才创建新修订和新校验 |

付费模型调用继续进入现有调用账本；结果未知不自动重发。视觉失败或待校正不应使已成功声音被再次生成。

### 5. 页面、Worker 与能力声明必须同步升级

创建页当前选择 visual 会提交 pixel_performance/1；不能仅调整后台而保留这一入口。能力接口须按实际启用模块和素材就绪状态公布 H5 支持。作品页分别显示声音可试听、视觉待校正、H5 可播放、视频未生成。

后台执行不依赖用户保持网页打开。Worker 重启、取消、并发编辑、资源缺失与历史版本读取均纳入验证。沿用本机素材与服务，首次接入不包含外部发布。

## 拟议流程与制品边界

冻结剧本后，声音准备与视觉规划可分别运行。视觉初步可行性检查应尽早报告主要缺口，但不能把全部视觉人工审核变成声音可试听的前置条件。

```text
story ──→ sound_plan ──→ audio ───────────────┐
   └────→ spine_plan ────────────────────────┤
                                            ↓
                                      spine_compile
                                            ↓
                                  校正 / 选定视觉修订
                                            ↓
                                    performance_package
                                            ↓
                                       H5 作品交付
```

阶段名为设计建议；独立修订过程通过明确提交恢复任务，不能在 GET 或页面刷新时触发生产。

拟议制品：

- SpineCapabilitySnapshot：人物、场景、面部、家具及编译器版本的固定引用。
- SpineVisualPlan：基于源场/行 ID 的选角、选景、动作、表情及相对时间安排，附制作选择与缺口。
- SpineStagePreview：复用已验证的 3.1 舞台结构，并绑定本任务来源及精确音频/时间轴哈希。
- PerformanceManifest：绑定脚本、声音、时间轴、选定预览、修订和审核状态的 H5 播放入口；不冒充 MP4。

以上制品进入同一作品的权限及内容哈希校验。后台不得用全局“当前目录”替代已固定的素材快照。

## 实施批次与可验收结果

### 第一批：契约、持久化和已有作品接入

新增 H5 输出分支、能力声明、阶段与必需制品契约；提取纯编译入口；实现视觉修订和播放清单。先用已有真实音频及确定性视觉方案验证同一任务的 H5 交付，模型桩仅用于离线调度测试，不能作为自动创作通过的证据。

退出标准：已有书店和多地点作品均可产生新的统一交付记录，旧来源与声音哈希不变；视觉失败时声音仍可播放；旧视频、音频与 stage-preview 入口仍可读取。

### 第二批：自动视觉规划与时间绑定

接入固定能力目录、模型方案与独立审查、相对时间锚点编译、有限修复及具体问题报告。声音继续沿用已有 sound_bridge/1，不重写已有声音工作流。

退出标准：覆盖普通对白、移动、坐家具、跨场、零时长动作及不支持动作；错误方案不能进入“完整演出”状态；真实模型结果单独记录，通过率以实际样本为准。

### 第三批：统一页面与完整新任务联调

创建页提供新版 H5 目标，作品页展示声音、视觉及待处理项，编辑后能提交新版本并恢复。以一部短篇从创作请求开始完成真实剧本、配音和 H5 演出，分别保留技术结果和人工验收状态。

退出标准：刷新、关闭页面、Worker 重启不导致重复生成；表情或走位调整新增 TTS 调用数为 0；音频重制会使旧视觉时间绑定失效；并发保存不丢改动；错误归属和错误哈希拒绝访问。
