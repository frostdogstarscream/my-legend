## 本轮发现的问题

### P1：混合声音描述被整体误判为控制指令

源行 `ep1-s1-l1` 是“翻找抽屉的轻微碰撞声，突然停止”，且处于全剧开头。该行包含需要实际发声的翻找碰撞，以及其后停止，不能整体视为已有声音的停止指令。

分类模型将它判为 `control_only`；编排最终只保留零时长 `action_note`，无对应音效素材。App 也显示为“动作记录 · 0:00”，第一条对白从 0 帧开始。原文字面被保存，但声音语义遗漏，不能以源事件覆盖率 100% 判为内容完整。

### P1：审核发现错误后，修复无法返回分类阶段

证据链来自 AudioArrangementEvidence.responses：

1. attempt 0 的独立审核指出 `missing_sound_component`，明确要求补充翻找碰撞声。
2. attempt 1 的计划尝试增加声音，但固定分类生成的 schema 将该行 sounds 限制为最多 0 项，出现 `too_long` 验证错误。
3. attempt 2 回到空声音方案，最终审核通过，开场缺声仍未消除。

这不是音效供应商中断，也不是生成接口不可用，而是分类、约束和修复路径形成冲突。最终审核未能保持首次发现的实质问题。

建议下一轮实现：

- “声音发生 + 停止/渐弱”等混合描述保留声音任务；只有确实控制已建立声源且不包含新发声过程的内容才能整体标记 control_only。
- 语义审核提出分类错误或缺失声源时，允许返回分类阶段并重建后续约束，形成新的可追溯制作包；计入统一修复预算。
- 保存未解决问题清单；不能仅因最后一次审核通过就清空先前的 missing_sound_component。超过预算仍未解决时停在待处理状态。
- 增加确定性的回归案例：开场“翻找声突然停止”必须产生音效；真正的已有背景停止必须走控制；两种情况不能互相替代。

### 待听审：停顿与复合音效效果

“短暂停顿”和“两人沉默片刻”当前是零时长标记，没有单独在时间轴中增加停顿。实际听感是否足够自然，需要听审；不能把标记的存在视为节奏已经实现。

其余复合音效合并为代表性单份素材，并记录简化说明，符合当前允许适当降低复杂音效标准的方向。但钥匙掉落的辨识度、声音先后关系和配音表演尚未人工验收。
