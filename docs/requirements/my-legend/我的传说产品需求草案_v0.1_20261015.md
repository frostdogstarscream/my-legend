# 我的传说产品需求草案

2026-10-19 范围更新：独立 API 生成剧本、广播剧和视觉表演，及无需开发会话介入的整合验收，按[独立生产实施计划](独立生产实施计划_v1.0_20261019.md)推进。该主线将能力范围内的自动视觉制作纳入核心目标；下文保留 2026-10-15 的历史方案与当时状态。

版本：0.1  
日期：2026-10-15  
状态：用于范围评审的建议稿，尚未冻结上线范围、排期和商业方案。  
对应基线：我的传说 uni-app 前端原型 0.2.0。

## 1 产品定位与首版目标

我的传说面向希望创作、阅读和收听故事的个人用户，以角色为创作入口，将用户的灵感加工成可以修改、保存和播放的作品。首版建议围绕“我的角色、我的故事、我的声音作品”形成连续体验。

建议首个可对外邀请用户使用的版本完成：选择角色与题材，输入灵感，生成真实故事，编辑并确认内容，改编剧本与选择声音，生成音频，在手机上收听并保存作品。视频先支持接入已有成品；自动视觉制作作为后续能力扩展。

目标用户暂按个人故事创作者和故事收听者设计，具体年龄、付费意愿和使用场景待确认。现有卡通插画不作为产品只面向儿童的依据。

客户端继续沿用当前 uni-app 工程。旧技术方案中关于 Kotlin 客户端的建议作为历史方案保留，不用于替换当前已选择的客户端路线。Android 内测、H5 辅助验证和小程序能力分别制定验收范围；同步上线哪些终端在本版评审中确定。

## 2 当前能力与主要缺口

当前工程注册了登录、首页、创作、故事、角色、我的、商城、详情、进度、阅读、角色详情和演绎共 12 个路由。默认使用本地示例数据；真实请求适配层不代表服务端已经提供对应能力。

| 模块 | 当前前端能力 | 距离真实产品的缺口 |
|---|---|---|
| 登录与个人资料 | 表单、演示身份、会话缓存、退出 | 真实身份、账号归属、会话撤销、资料与数据管理 |
| 创作与故事 | 灵感输入、选角、本机草稿、搜索筛选 | 云端存储、正文编辑、版本恢复、分页与跨设备同步 |
| 生成流程 | 本地计时进度与固定示例章节 | 真实异步任务、内容结果、取消、失败恢复、资源消耗记录 |
| 角色 | 示例档案、带入创作 | 统一角色身份、人设与声音版本、角色获取和服务端权益 |
| 阅读 | 示例正文、字号、按作品保存本机章节位置 | 真正的章节数据、阅读位置与首页状态一致、云端进度 |
| 声音制作 | 试听和伴读入口说明 | 剧本、说话人分配、音色试听、分段制作、局部重做与成品音频 |
| 视频演绎 | 场景、人物、示例时间轴，保留真实 video 分支 | 实际视频与声音、真实时间轴、网络及全屏真机验证 |
| 商城与会员 | 权益预览、订单空态、本机兑换演示 | 服务端商品、账本、订单、权益和实际支付 |
| 内容与运营 | 前端样例内容 | 角色/模板/素材管理、任务追踪、内容处理、反馈和成本上限 |

当前最需要补齐的环节是作品的编辑、制作和交付。应把故事正文、可制作剧本、声音成品和视频成品连成同一份作品，避免用户在多个页面重复创建内容。

## 3 用户与工作台

普通用户负责选择角色、提出创意、修改内容和确认声音，后台制作服务负责异步执行，运营或制作人员处理角色模板、素材、内容问题和异常任务。

保留现有“首页、创作、故事、角色、我的”五个底栏。建议将故事详情扩展为作品工作台，在作品内提供“故事、剧本、声音、演绎”四个内容区，不再增加一级底栏。

| 入口 | 建议承担的职责 |
|---|---|
| 首页 | 最近阅读/收听、继续创作、正在进行的任务、少量官方示例 |
| 创作 | 灵感、粘贴已有文本、题材、角色、篇幅与创作方式 |
| 故事 | 我的作品、草稿、制作中、已完成、搜索与筛选 |
| 作品工作台 | 正文编辑、版本确认、剧本与选声、制作进度、成品播放 |
| 角色 | 我的角色、角色档案、声音样例、添加角色 |
| 我的 | 资料、使用额度、偏好、反馈与数据管理 |

会员和商城可以继续保留设计入口，首轮内测以真实可用的功能为准。未接通的交易能力应显示明确状态，不用演示余额代替真实账户数据。

## 4 主要用户流程

### 4.1 从灵感创作

用户选择角色和题材并输入灵感，保存云端草稿，再提交生成任务。后台返回任务标识，用户可以离开页面并稍后查看结果。生成完成后进入正文编辑，保留原生成版本，用户确认后形成可用于下一步制作的内容版本。

### 4.2 从故事制作声音

用户将已确认故事改编成剧本，查看分场、说话人和台词，确认角色声音。开始制作前展示制作范围和额度消耗规则；一次提交后自动完成约定范围，不要求用户逐句重复确认。制作完成后可试听成品，对不满意的片段局部重做，再选择要使用的音频版本。

故事创作与剧本改编是两个阶段。旁白、人物对白、动作和音效需求分别表达，动作说明不作为朗读内容。用户界面可采用简化的逐句编辑，详细的表演和时间轴参数放在展开项或制作后台。

### 4.3 阅读和收听

用户从首页或作品进入阅读/播放，读取该作品对应版本的实际内容与媒体。暂停、拖动和章节切换更新独立的阅读或播放位置。返回首页后应显示一致的“继续阅读/继续收听”位置。

### 4.4 视频演绎

第一步允许制作人员上传或登记已有视频，绑定作品版本、封面、角色和对白时间段。用户能够观看真实视频，字幕与人物高亮以实际播放时间更新。第二步再评估自动视觉编排和视频生成，不把静态场景时间轴视为成品视频。

## 5 首版功能范围

P0 表示真实产品闭环必须具备；P1 表示首个稳定版本后的重要增强；P2 表示验证核心价值后再投入。具体需求与验收条件见[功能清单与验收草案](功能清单与验收草案_v0.1_20261015.md)。

| 优先级 | 功能 | 产品要求 |
|---|---|---|
| P0 | 体验与账号 | 示例体验和真实账户分开；个人作品由服务端鉴权与归属控制 |
| P0 | 作品管理 | 保存、重命名、编辑、删除、恢复指定版本和跨设备读取 |
| P0 | 真实故事生成 | 后台任务、阶段与结果、失败说明、重试和取消 |
| P0 | 正文编辑与确认 | 修改生成内容、保存版本、明确后续制作基于哪一版 |
| P0 | 角色与剧本 | 明确每句说话人、旁白与动作；检查缺失人物与角色声音 |
| P0 | 选声与声音制作 | 使用可试听的声音配置；分段结果、局部重做、成品音频 |
| P0 | 阅读与播放 | 真实内容、真实时长、进度保存、暂停/跳转/异常恢复 |
| P0 | 任务与额度 | 查询进行中的任务、重复提交保护、消耗记录和服务端限额 |
| P0 | 最小管理后台 | 角色、声音、模板与素材管理，任务查询与异常处理 |
| P0 | 内容与数据管理 | 作品默认私有、删除及分享状态、内容问题处理和用户反馈 |
| P1 | 真实视频播放 | 登记已有视频、实际时间轴、字幕与角色联动、全屏及错误恢复 |
| P1 | 模板与续写 | 少量可维护模板、章节续写、已有文本导入和创作提示 |
| P1 | 分享与导出 | 用户明确选择分享范围，支持撤回；文件导出按终端能力验收 |
| P1 | 播放增强 | 后台播放、定时关闭、播放队列、缓存管理，按首发终端确认范围 |
| P2 | 商业化 | 会员、额度套餐、付费角色、订单、真实账本与支付 |
| P2 | 深度互动 | 角色聊天、剧情选择、多人创作、社区推荐与评论 |
| P2 | 高级制作 | 自动复杂视觉制作、自定义声音、完整移动端混音编辑 |

此处将声音闭环列入首个可邀请用户版本；可以先交付“真实创作与阅读”供内部联调，再逐步接声音，避免同时开发所有媒体能力。

## 6 角色获取与 NFC

历史 Android 方案明确讨论过 NFC 扫描添加角色。本草案保留该需求为独立的 M0-NFC 验证项，本版是否仍要求与内容闭环同时验收需要确认，不因客户端改用 uni-app 而视为已实现或自动取消。

最小流程是扫描已配置卡片，后台查到对应角色，加入当前用户角色库；同一用户重复扫描不重复添加。角色加入后从角色库选择使用，不要求每次创作重新刷卡。官方赠送、兑换码、二维码和后续购买可共享同一套添加角色规则。

NFC 仅提供识别信息，角色定义和映射放在后台。首轮沿用“能刷卡添加”的范围，不额外扩展芯片独占绑定、转赠或防伪系统。Android 原生接入及实机读取单独验收，小程序和 H5 不预先承诺相同能力。

## 7 内容与状态规则

### 7.1 作品和派生内容

一份作品可以有多个正文版本、剧本版本、音频版本和视频版本。制作任务必须记录输入版本；修改内容后将受影响成品标记为待更新，不把旧音频展示为新正文的对应成品。

角色模板、作品中的人物身份、声音配置和视觉素材分别管理。同名人物不自动合并，人物与声音的对应关系通过明确标识建立。台词引用公共事件或台词标识，不靠人物出现顺序或段落符号猜测说话人。

### 7.2 四类状态分别显示

| 状态 | 表达内容 |
|---|---|
| 内容状态 | 草稿、待确认、已确认、已归档等内容阶段 |
| 制作状态 | 排队、运行、成功、部分失败、失败、已取消 |
| 阅读位置 | 章节、段落/位置和最近阅读时间 |
| 播放位置 | 媒体标识、媒体版本、实际播放秒数和最近播放时间 |

当前已有独立的 `GenerationTask.progress`，阅读章节与字号也有本机记录；`Story.progress` 的作品级语义及云端阅读/播放记录尚未形成统一契约。正式接口应保留任务进度，并明确作品内容状态、阅读位置和媒体播放位置，避免今后混用。故事生成成功、配音成功、视频就绪和作品可分享也分别判定。

### 7.3 重试与局部重做

重试同一请求不重复创建制作任务或重复记账。某句配音失败只处理失败范围，已有成功素材继续保留；重新选择某句音频后重新测量时长并更新受影响时间轴。取消的范围、已发生的实际消耗与后续停止行为须在契约中明确。

## 8 后台与集成职责

uni-app 负责输入、编辑、导航、任务状态和媒体播放。业务后台负责账户、作品归属、版本、角色库、额度、任务与媒体访问；制作工作流负责故事/剧本处理、TTS、音效和视觉适配；媒体存储提供可访问且受控的资源地址。

已有故事和制作工程作为复用候选，先完成接口与交付物核对，不预设历史开发包等同于在线服务。业务服务对外统一任务和媒体契约，客户端不直接携带模型密钥，也不承担最终账本计算。

最小管理界面应允许管理角色、人设和声音版本，登记封面、音频和视频，查询失败任务与关联记录，设置额度和并发限制，处理反馈及分享内容。首期可利用已有管理后台能力，不要求另造完整运营平台。

## 9 终端与播放要求

| 范围 | 建议验收策略 |
|---|---|
| H5 | 用于快速体验、表单与主流程验证；浏览器权限、播放和文件行为独立核验 |
| Android App | 真实登录、创作、音频、演绎、异常恢复；如纳入 NFC，增加硬件实机验证 |
| 微信小程序 | 按确认范围验证登录、合法资源地址、包体、播放与平台生命周期；不以编译成功代替实机结果 |

后台音频不是简单地让页面播放器继续计时。DCloud 的背景音频管理 API 列明支持 App 与微信小程序，H5 不支持该 API，因此后台/锁屏播放须按终端分别验收。[背景音频文档](https://uniapp.dcloud.io/api/media/background-audio-manager.html)

视频的全屏方向、控件和部分属性也有平台差异；字幕与人物联动以媒体时间更新为依据。[video 组件文档](https://uniapp.dcloud.io/component/video.html)

## 10 数据与基础运营

个人草稿和未分享作品默认私有，读取、修改和删除都由后台验证归属。分享以具体作品版本为对象，撤回后应改变真实访问状态。删除、缓存清理和云端媒体清理的处理范围需明确，正式保留周期另行确定。

演示身份、示例内容和本机模拟余额不能混入真实账户。日志优先记录请求/任务/作品标识及错误阶段，避免记录密码、密钥和不必要的完整私密创作内容。

输入及成品应有可配置的内容检查和问题处理入口；公开分享前增加相应处理流程。面向何种年龄、是否允许用户公开投稿、内容来源授权及发行渠道要求在上线评审中确认，不在本稿中代填法律结论。

## 11 里程碑与验收

| 里程碑 | 交付目标 | 验收依据 |
|---|---|---|
| M1 真实创作与阅读 | 账号、云端作品、生成任务、正文编辑与版本、真实章节阅读、最小任务管理 | 真实后台结果、跨账户隔离、跨设备草稿、失败重试与内容版本 |
| M0-NFC 独立验证 | 如延续历史范围，刷卡添加正确角色并去重 | Android 真机、不同角色卡、重复扫描、重启后仍保留角色 |
| M2 声音作品闭环 | 剧本、角色声音、分段配音、局部重做、音频成品与播放 | 实际音频、说话人及台词核对、人工听审、实际时长与播放恢复 |
| M3 演绎与分发 | 已有视频接入、对白同步、分享/导出；评估自动视觉制作 | 真实媒体与终端行为、版本一致、可撤回分享或可播放导出文件 |
| M4 商业与扩展 | 根据核心使用数据决定会员、付费角色、互动和社区 | 成本与使用数据、独立交易验收及确认后的范围 |

M1 是内部联调可用版本；M2 建议作为首个邀请真实用户体验的产品版本。M0-NFC 是否成为该版本的发布条件由范围评审确定。此处不填写工期，估算应在确认服务端可复用程度、人员与媒体方案后完成。

验收不只检查 HTTP 成功和任务状态。应分别核对内容、声音、视觉、时间同步、数据归属及终端行为；结构测试与编译检查不能代替这些结果。

## 12 成效指标

| 指标 | 口径 |
|---|---|
| 首次成品完成率 | 进入真实创作的用户中，完成首份可播放作品的用户比例 |
| 制作成功率 | 分别统计故事、剧本、声音和视频任务的成功、失败与取消；重试单独记录 |
| 首次成品等待时间 | 从提交到成品可播放的实际耗时，区分排队和执行 |
| 用户接受程度 | 首次结果被确认使用的比例、局部重做次数及反馈原因 |
| 制作成本 | 每份作品实际模型/媒体消耗、失败重试消耗及单位音频时长成本 |
| 回访与继续创作 | 用户再次阅读、收听或完成下一份作品的行为 |

目标值待内测样本和实际成本数据确定，不用当前固定示例任务推算正式效果。

## 13 待确认事项

1. 首批用户以自己创作为主，还是以收听/观看官方内容为主；两者在首页的比重。
2. Android、微信小程序是否同时进入首轮发布；H5 是否仅用于演示和联调。
3. 本版是否延续 NFC 首轮验收要求，以及可用卡片与角色映射由谁提供。
4. 首次成品以纯音频为主，还是要求同步交付已有视频；自动视觉制作的投入范围。
5. 真实故事、TTS、音效与视觉服务中，哪些已经可接、哪些需继续适配。
6. 内测额度与成本预算、是否商业化、作品是否允许公开分享。
