## 使用流程

1. 从已有配音作品打开 H5 剧情演绎，恢复一个已保存版本。
2. 点击“保存为正式 H5 版本”。若有未保存修改，页面要求先“应用并保存”。
3. 自动进入正式制作记录，后台依次执行“核验已有演绎”和“打包 H5 版本”。关闭页面不影响后台任务。
4. 完成后点击“播放 H5 版本”或“继续编辑并另存”。修改先保存为新的预览，再交付形成子版本，原版本不变。

相同来源、预览和父交付的重复按钮提交复用本地保存的幂等键；未知网络结果可重试，不重复创建。不同修改形成新预览，使用新键。没有可覆盖的全局最新版本指针；并发另存保留各自分支。

## 接口及后台行为

- `POST /api/v1/production-jobs/{source_job_id}/h5-deliveries`：请求包含 `preview_sha256`、`idempotency_key`、可选 `parent_job_id`。服务端派生所有者、作品和来源版本，返回 202 与新制作任务。
- `GET /api/v1/production-jobs/{job_id}/h5-performance`：返回经过哈希和资源校验的固定预览与 PerformanceManifest。
- 既有 playback 查询增加可选 `performance_manifest`，可用输出增加 `h5`；原音频/视频清单格式保留。H5 不生成 Video 制品。
- capabilities 增加 `h5_delivery`，模式为 `saved_performance_import`，支持预览 3.0、3.1；创建故事入口未开放自动 H5 生成。
- 内部 saved_performance 请求只走 `performance_import → performance_package`。普通创建任务接口拒绝客户端直接提交这一内部来源，要求使用专用入口。

导入保存原始预览字节为 SpineStagePreview，哈希与原预览相同，不改写内部原任务标识；关联已验证的剧本、混音、实测时间轴及声音安排依赖，另存 PerformanceSource 和 PerformanceManifest。制品查询仍绑定当前交付任务的所有者与制品登记。

目录和图片资源以固定哈希验证，保留原编译/规则版本、所有轨道、覆盖与遗漏记录。旧 3.0 不自动升级，新旧预览按原规则重新校验。素材仍由本机不可变运行目录提供；交付不是脱离本机资源的便携包。

后台导入/打包为确定性本地执行，不使用模型调用账本中的付费操作。未处理动作不会使打包失败；无效资源、错误来源或损坏制品会失败，原作品音频和演绎仍可打开。

## 启动与隔离

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ops/my-legend/Start-SpinePreview.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File ops/my-legend/Start-H5DeliveryWorker.ps1
```

预览启动脚本为新启动的 API 声明两个新增模块；已启动的旧 API 需要有针对性地重启后才能加载接口。专用 Worker 使用 `--only-configured-stages`，仅声明 performance_import、performance_package；不启动生成 Worker。其 PID 保存在本机 runtime/my-legend-story/h5-delivery-worker.pid，重复启动会核对进程身份。

队列领取和过期/取消清理都按专用阶段收窄。H5 取消操作同样限定新增阶段，避免清理历史生成任务。本轮没有数据库结构迁移。
