# 大纲批准前能力审查与第五轮试跑

## 改动与边界

第四轮已确认不支持动作在大纲阶段被模型自行引入并被自动策略采纳。新增 `production_plan_audit/1.0`：原生大纲模型生成后、PlanPreview 保存和任何批准之前，按锁定素材能力审查所有非空文本字段。嵌套的声音提示、人物设定、总结和主要节拍都纳入覆盖，不仅扫描 action 字段。

审查结果必须返回完整、有序、逐字一致的 JSON 字段路径和引用，未知动作名保留为不支持项，不能映射成 wait/react。用户明确要求但不支持的必要事实必须引用原始创意中的真实文字，并返回能力缺口；提议大纲自行新增的错误细节允许在批准前修复一次。修复后重新审核，并继续执行原生大纲角色、结局、因果和集数/时长约束。

新增策略只在生产 API 的视觉创意任务中挂接。普通 StoryGenerate 调用保持原路径；已发布历史剧本和已批准大纲不被改写。原始模型请求/响应保存在已有 model-evidence，生产事件记录计划及审核指纹与问题计数。模型审查不代表人工内容验收。

大纲修复、正文修复、时长修复、JSON 修复共用故事阶段修复次数。检查中另发现原生表演标注循环的后续尝试没有独立修复标签，现已标记 `performance_annotation_repair` 并纳入同一预算；普通无生产绑定调用的原生次数策略不变。
