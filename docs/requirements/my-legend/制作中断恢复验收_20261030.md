# 制作中断恢复验收（2026-10-30）

本轮按用户最新要求只处理制作卡住后的状态、查询与恢复操作。实施途中新增的大纲、写作提示、时长选择理由和短篇规则已撤回，保留此前的自动时长实现。

## 页面行为

| 实际状态 | 页面说明与操作 |
| --- | --- |
| 正在执行 | 按阶段显示正在写故事、正在配音或正在准备舞台，不因耗时长就判失败 |
| 可复用原任务继续 | 显示已保存完成部分，提供继续制作 |
| 原调用结果未知 | 提供查询结果和重新制作；查询失败时保存“暂时无法查询结果”的状态 |
| 原任务已失败且不能复用 | 提供重新制作，避免继续执行同一失败任务 |
| 已有完成制品 | 保留剧本、声音和作品入口 |

首页、故事集和制作详情使用后端统一的恢复信息。普通读取、轮询和刷新不会触发生成。查询结果只读取已记录的上游任务，不自动恢复或提交新任务。

重新制作直接创建同一作品的新版本，保留来源版本及旧调用记录。没有成功剧本时从原灵感重新开始；已有成功剧本时复用剧本重做声音；已有完整声音时复用声音重做基础舞台。幂等键防止同一操作因重复请求创建多个版本。

## 代码与数据

- `production/recovery.py` 计算恢复状态；`flows.py` 与 `works.py` 返回统一信息。
- `POST /production-flows/{id}/reconcile` 检查所有者和版本号，保存查询结果；`resume` 单独校验可恢复条件。
- `006_flow_recovery.sql` 为流程增加查询记录，已应用到本机数据库。
- 前端制作页及列表使用恢复文案与操作，停止对中断作品显示等待制作的占位提示。
- 当前阶段的失败记录必须匹配对应查询结果，不能用大纲查询成功放行已经失败的正文阶段。
- 声音任务已取消或失败但仍有未知调用时，用户主动重新制作也能建立新版本；仍禁止自动重放，旧未知调用原样保留。
