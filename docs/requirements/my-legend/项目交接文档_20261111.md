## 3. 本机启动与入口

### 3.1 日常启动

在当前电脑双击项目根目录的 `启动交互式前端.cmd`。它调用 `ops/my-legend/Start-InteractiveFrontend.ps1`，再使用 `Start-Creation.ps1` 和 `Start-SpinePreview.ps1` 启动服务。

```powershell
Set-Location D:\Code\AIToy
.\启动交互式前端.cmd
.\启动交互式前端.cmd -Page create
.\启动交互式前端.cmd -PreviewOnly
.\启动交互式前端.cmd -NoBrowser
```

`-Page` 支持 `characters`、`create`、`stories`、`home`。默认打开角色页。`-PreviewOnly` 启动预览所需服务，已存在的生成进程仍会继续执行。后台服务可在启动窗口关闭后继续运行。

根目录 CMD 和 `交互式前端启动说明.md` 被当前 Git 忽略规则排除。接手源码时使用已纳入 Git 的 PowerShell 入口，在 PowerShell 7 中执行以下命令。

```powershell
Set-Location D:\Code\AIToy
.\ops\my-legend\Start-InteractiveFrontend.ps1 -Page create
```

启动器会检查已有进程身份、端口和服务就绪状态。`Start-Creation.ps1` 还会执行迁移、角色库同步，并启动或复用 Worker。运行中的队列可能继续处理已有任务。

接手新电脑时需完成以下事项。

1. 检出交付分支及提交，安装各源码模块的依赖，重建 Python 虚拟环境。
2. 根据 `Start-Creation.ps1`、`Start-SpinePreview.ps1` 及 `runtime/my-legend-production/workflows.json` 核对本机路径。
3. 恢复 PostgreSQL 数据及对应制品，迁移前保留可恢复副本。
4. 迁移本地角色、场景、骨骼、图集和运行时，保持目录哈希与引用关系。
5. 为新 Windows 用户重新配置服务及模型凭据。
6. 配置前端 `.env.local` 后启动服务，检查登录、已有作品读取和媒体访问。

`.env.example` 默认启用 Mock。真实本机接入需核对 `VITE_USE_MOCK=false`、本地后端开关及 `VITE_API_BASE_URL`，当前业务前缀为 `http://127.0.0.1:8895/api/v1`。

### 8.5 启动与运行环境

2026-11-11 实测确认的三个环境问题，已在 `ops/my-legend` 中修复。

- PowerShell 版本：`Start-InteractiveFrontend.ps1` 要求 PowerShell 7.4 及以上，启动器用 `Start-Process -Environment` 写独立日志。本机标准安装目录没有 PowerShell 7，入口会继续查找 PATH、用户级安装、应用商店别名和已有的便携运行时；也可用 `LEGEND_PWSH` 环境变量直接指定。
- PID 复用：pid 文件现在保存进程 ID 与启动时间。进程退出后系统可能复用该 ID，旧版会把复用当成冲突并中止启动；现在会把旧文件改名为 `.pid.stale-<时间戳>-<原因>` 留证后继续启动。回归检查见 `ops/my-legend/Test-StartupPid.ps1`。
- 服务日志：每个后台服务都有独立日志，位于 `runtime/my-legend-story/logs/<服务名>.out.log` 与 `.err.log`，不再依赖启动窗口输出。
- 自动化调用：请使用 `cmd /c "启动交互式前端.cmd -NoBrowser > 日志 2>&1"`。直接把启动器接到管道（例如 `| Out-String`）时，新拉起的后台服务可能让调用方一直等待；双击入口和文件重定向不受影响。

PostgreSQL 目前由启动器以独立进程启动，历史上出现过 `0xC000026B` 异常退出（2026-11-02、2026-11-06）。长时间生成前应先确认 55439 可用，失败时查看 `logs/postgres.log`。
