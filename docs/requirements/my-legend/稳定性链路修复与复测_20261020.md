# 故事与音频稳定性修复及复测（2026-10-20）

本轮范围为独立 API 和 Worker 的故事、声音编排、真实配音、音效、实测时间轴与混音链路。视觉制作保持暂停。此前三轮失败证据保留在 `runtime/my-legend-production/acceptance/stability-three-20261019-v1`，不改写其结果。

## 已实现的修复

1. **缩小模型输出范围。** 服务端固定原文、角色、来源引用与朗读操作 ID。模型只返回对应行的声音选择及时间关系；对白和旁白不能额外插入停止操作或改写原文。声音操作按源事件类型生成对应 Schema。
2. **相对时间替代结束秒数猜测。** 新编排的背景结束点必须关联具体操作，最终按真实素材采样帧解析。历史编排仍可读取。
3. **实测失败后的局部纠正。** 保存完整的生成素材快照和实测帧数。可修复的时间编译错误进入受预算限制的时间字段补丁，再经过独立审核；修复阶段只能调整时间关系，复用已生成的 TTS 和音效。重放不重新调用生成供应商。
4. **故事局部修复。** 修复响应只包含指定行替换、插入或经核实的重复行移除，并校验原文及位置。合并后重新校验完整剧本。控制类音效保留为合法控制指令，不一律强迫改写成动作。
5. **软长度提示。** 目标 90 秒时，推荐朗读字数仍为 252–410；硬保护区间由 189–504 调整为 95–504，按对白与旁白字符统计（含标点）。超出推荐区间提示，超出硬保护区间修复或拒绝。TTS 指令软阈值 360、硬阈值 600 保持不变。字数估算不等于成片时长达标，最终仍报告实测时长。
6. **失败结算及恢复语义。** 已明确失败且产生供应商调用的任务保存调用计数并结算；不允许把它当作零成本预检失败反复恢复。App 对方案错误展示对应原因并隐藏容易误导的直接恢复入口。调用结果未知仍需单独核实。

## 三轮之后的追加修正

- `audio_choices/1.1` 使用独立实例生成提示，明确不返回 Schema、不返回整份 events；错误返回 Schema 时提供专门反馈。
- 新的 `audio_review_choices/1` 只要求逐行问题类型、逐字原文依据和受影响操作。每行允许的问题类型由程序按事件类型生成；旁白/对白不接受新增音效要求，动作说明不强制新增声音。复核结果由程序组装回原有 2.0 制品，不改变历史播放接口。
- 一次性素材可包含自然结束的完整动态，背景自然结束不要求额外停止操作；缺失独立声音、以音量冒充速度或另一声音等真实问题仍可阻断。
- 同一锚点的背景起止倒置或相等，在调用 TTS/SFX 前确定性拒绝；依赖真实时长的其他约束继续由实测编译器检查。
- 8 项定向用例通过，覆盖受限复核、伪造依据拒绝、真实遗漏仍失败、Schema/实例纠错与提前阻断不可能的背景区间。
