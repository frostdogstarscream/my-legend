# 剧本音频独立审查修复

## 修复依据与范围

首轮声音独立试跑 `story-audio-20261019-01` 技术成功，但原始需求要求旁白，交付却没有 narration；若干 sfx 包含气味和心理叙述。原生产前置审查只在请求 visual 时挂接，独立剧本/声音请求没有对应内容核对。

本次增加 `production/audio_readiness.py`，通过现有 StoryGenerate 的 `production_draft_policy` 扩展点，在表演注释和音频制作前执行。仅用于不含 visual 的生产请求；视觉仍暂停，既有视觉策略不用于声音验收。普通 StoryGenerate 请求若没有 production 绑定，保持原行为。

## 实际行为

- 生成阶段补充固定交付规则，要求保留明确的旁白、角色、关键事实和结局等要求，禁止把声音以外的叙述混入音效。创意内容仍作为数据传入，不拼接进系统规则。
- 审查模型引用用户需求原文逐项判断，同时完整覆盖正文全部行；代码校验引用确实来自输入、行号和原文按序匹配。伪造引用和缺行属于审查结构错误，不把它们当成剧本错误重写正文。
- 模型识别明确要求/禁止的事件类型后，由代码核对实际事件数量。没有要求旁白时不强制增加；明确禁止旁白时允许零旁白。语义是否真正满足要求仍是模型判断，不能宣称确定性地发现了所有需求遗漏。
- 音效只能包含可听的描述；相同的气味、内心叙述放在旁白或正常对白中不构成音效错误。非朗读动作允许正常的拿物、坐下等行为，不读取视觉素材库、不施加像素动作限制。
- 有实际缺陷时最多一次完整正文修复，再做一次独立复审；仍失败则以安全错误码结束，不继续花费音频调用。模型 JSON 修复、正文修复和原有修复共享故事阶段的总修复预算，不另开无限重试。
- 每轮记录正文及审查哈希、问题数量、明确问题和需求核对结果；真实调用沿用原供应商账本。未知外部调用不会作为内容缺陷自动重试。
- 修复仍经过原生角色、结构、连续性和朗读字符预算校验。字符预算不是实际音频时长；本次没有解决音效/停顿合入后的总时长控制，也没有宣称完成发音与人工听审。
