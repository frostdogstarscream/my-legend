# 统一播放接口与验收

本接口用于独立生产任务的剧本、广播剧和视觉结果展示。旧历史制作接口保留，历史结果不会自动迁移或重新制作。

## 接口

`GET /api/v1/production-jobs/{job_id}/playback` 使用与任务接口一致的服务端身份校验。无身份返回 401，不属于当前用户或不存在的任务返回 404。读取只消费已提交的制品登记，不领取任务、不调用模型、不写新制品。

业务 envelope 的 `data` 包含：

| 字段 | 含义 |
| --- | --- |
| schema_version | production_playback_view/1.0 |
| job_id / job_status | 当前任务及其状态；失败状态不隐藏已完成结果 |
| available_outputs | script、audio、visual 中实际已就绪的项 |
| manifest | production_playback/1.0；尚无剧本时为 null |

播放清单含任务、作品、来源版本以及 script/audio/timeline/video/poster 引用。每项引用含 ArtifactRef 和相对的 content_path；路径必须精确匹配当前任务与文件哈希，不接受外部地址或凭据参数。

纯剧本清单只有 script。广播剧必须同时具备 audio、timeline、sample_rate、total_frames 和 duration_seconds。视频额外要求 video、poster 和 visual_profile。时长等于 total_frames / sample_rate，禁止将目标时长当作媒体时长。

声音时间轴内的 audio_sha256 必须对应混音文件；视频保存的播放清单必须与当前任务登记的剧本、音频、时间轴、视频和封面全部一致。来源错配、媒体类型错配、时间错配均拒绝作为可播放结果交付。

`human_review` 仅支持 pending/not_required，`publication` 为 not_requested。技术检查或自动制作不代表人工认可或公开发布。

## 客户端接入

作品页分别读取任务状态与播放视图，只展示播放视图中已就绪的媒体。客户端再次检查任务、来源版本及内容路径，下载时通过 Authorization 请求头鉴权，播放器使用临时本地文件或 H5 Blob 地址，不将 token 写入链接。

任务查询和播放查询不是同一数据库快照，阶段刚结束时允许下一次轮询补齐展示；同一任务的来源版本固定。关闭页面停止轮询，不停止后台制作。

## 验证边界

- 协议测试覆盖三种输出组合、所有媒体的跨版本拒绝、跨任务/外部/带 token 路径拒绝、媒体类型、时长和依赖完整性。
- 只读视图测试覆盖视觉失败后剧本与广播剧继续可用，并核对读取前后任务对象和制品目录无变化。
- HTTP 路由测试覆盖身份、作品归属、空结果查询。
- 五阶段测试使用替身故事和模型、合成声音，实际执行原 Dart 编排与 FFmpeg 编解码，生成清单再通过播放视图核验。它不是新输入真实模型验收。
- 本机实际服务仅检查鉴权、任务列表和不存在任务的播放查询；尚无正式独立生产任务可供真实成片页面验收。

协议实现：`production/playback.py`。可导出的正式 JSON Schema：`production/schemas/PlaybackManifest.schema.json`。变更协议时须同时调整生成端、查询端和客户端，不应仅修改静态 Schema。
