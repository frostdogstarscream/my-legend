## 接口、契约与版本

新增 `POST /api/v1/production-jobs/{job_id}/stage-preview/suggest-face`：

```json
{
  "profile": "life_v1",
  "source_preview_sha256": "已有不可变预览的完整SHA256",
  "mode": "offline_rules",
  "max_suggestions": 32,
  "include_diagnostics": true
}
```

身份/任务归属检查先于预览和制品读取。服务端通过 `read_life_preview` 与 ArtifactStore 读取实际不可变预览、StoryDelivery、MeasuredTimeline 和目录，不接受客户端自带文本、资源 URL 或模型时间戳。接口不调用 `save_preview`，不更新原工作单，不启动生成任务。

返回 `legend_face_suggestions/1`：源预览和 StoryDelivery 哈希、来源版本、音频/时间轴/目录/Profile 哈希、采样率、总帧数、完整演员绑定、稳定请求指纹、候选和诊断。候选使用原 FaceCue；证据三元组、短语、操作 ID、置信度与规则版本位于外层 evidence。

候选元信息只在只读响应/审阅界面，不自动持久化；接受的 cue 投影为原 FaceTrack，通过既有保存接口生成新版本。没有给旧 FaceCue 增加来源字段。需要保留原建议审计记录时应保留响应；本轮对应记录在本机证据目录。既有 `legend_stage_script/0.3`、`legend_face_track/1`、`legend_dialogue_track/1` 和两个已发布 Profile 均未改解释或哈希。

请求严格拒绝额外字段、未知模式、字符串开关、布尔/字符串数量。默认 32 条，允许 1–64 条候选。输入上限为 512 来源行、32768 字符、2048 时间轴操作；诊断最多 256 条。超限弃权，不截断后继续猜测；FaceTrack 原有 512 条容量限制继续生效。

## 规则与保守性

规则引擎 `zh_explicit_face/1` 支持“惊讶/大吃一惊/睁大眼睛（含‘了’）”和“眯眼/眯起眼睛（含‘了’）/挤眼”。不把开心、笑了、生气、难过或单纯问句映射为已有眼形，也不额外添加 neutral cue。

否定、转述、疑问、将来、假设或不确定语境整句弃权。主体解析使用动作前的名字/别名；对白“我”只指已绑定说话人；“她/他”必须有同一来源行内唯一明确的先行角色，不按性别或舞台顺序猜测。多个表情共用来源且缺少逐词锚点时弃权。

时间来自证据所在且匹配字幕来源的实测 speech 区间，采用 `[start_frame,end_frame)`，支持 1.x 平铺事件和 2.0 operations。零长动作标记、planned_silent_hold 和 visual_estimate 不充当表情持续时间；无锚点报告 `NO_ANCHOR`。

人工表情优先：同演员同通道冲突整段跳过，不裁掉或重写人工 cue；blink 可共存，原面部运行时继续保证闭眼优先。涉及 pick/lie、非白名单动作或隐藏状态时整体弃权。当前处理偏保守：角色先前被隐藏，即使后来出现，部分后续候选仍可能被排除。

候选确定性排序、稳定 ID，合并后沿用服务端 `validate_face_track`。不修改朝向、身体、换装、镜头和字幕。诊断包括 `NO_EXPLICIT_EXPRESSION`、`UNSUPPORTED_EMOTION`、`AMBIGUOUS_ACTOR`、`AMBIGUOUS_EXPRESSION`、`NEGATED_OR_QUOTED`、`NO_ANCHOR`、`PROFILE_UNAVAILABLE`、`PROTECTED_ACTION`、`CONFLICT_WITH_MANUAL`、`CONFLICT_WITH_CANDIDATE`、`INPUT_LIMIT`、`TRACK_LIMIT`。

离线候选的 `confidence=0.98` 为固定规则证据等级，不是经语料校准的统计概率；界面以原文证据供人工判断。

## UI、撤销与故障隔离

生活演绎页新增“自动表情建议 · 离线规则”。先明确启用并保存表情 Profile；有未应用修改时先应用或撤销。生成不会停止原声音或切换舞台。

候选默认不勾选，可查看演员、表情、时间、来源行、证据、诊断，并定位、删除或关闭。加入草稿后使用原表情简表修改演员/语义/时间/开关，最后“应用并预览”。“撤销加入的建议”只移除本次加入的 cue，保留其他人工内容。

源预览、Profile、StoryDelivery 和全部演员/音频绑定必须一致。请求期间修改草稿、切换版本/成品或取消请求，迟到结果会被丢弃。接口失败只影响建议面板。最终保存仍需原服务端严格校验，失败保留已应用版本。
