# 我的传说：真实故事服务接入

2026-10-19已完成一个真实模型样例的大纲确认、正文生成、质量检查和原型章节阅读，结果与能力边界见[联调验收记录](联调验收记录_20261019.md)。

## 本机启动

在普通 Windows 用户的 PowerShell 中执行，并保持窗口打开：

```powershell
Set-Location 'D:\Code\AIToy'
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\my-legend\Start-Prototype.ps1
```

访问 http://127.0.0.1:5193/ ，点击“进入本机创作”。当前是单人本机联调入口，正式账号、会员和支付未接入。旧演示草稿仍留在原浏览器存储，不被服务器覆盖；正在编辑的墨羽、灵墨旧编号会映射到对应的服务端角色。

故事创作流程：填写名称/创意/题材/角色 → 生成故事大纲 → 查看大纲 → 提交修改意见或确认当前版本 → 后台生成正文和演绎标注 → 故事详情 → 章节阅读。本轮新建故事默认一集、目标90秒；这是创作约束，不是配音后的实测时长。

生成、修订和失败重试会调用真实 MOMA 模型并可能消耗额度。大纲确认后才创建正文任务；重复确认使用同一个任务。失败后保留创意、审批快照和失败历史，点击“重试当前任务”显式重试，不会把示例章节填成真实结果。任务页可以离开，之后从故事详情返回。服务重启后仍从数据库恢复任务；原 Worker 中断后的已失效租约按原项目规则处理，不承诺正在计费的请求可无损恢复。

按 Ctrl+C 关闭本次启动器创建的 API、Worker 和业务接口。独立数据库的数据目录保留，数据库进程可能继续运行；如需停止这个项目的数据库，使用精确目录：

```powershell
& 'C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe' -D 'D:\Code\AIToy\runtime\my-legend-story\postgres-data' stop -m fast
```

## 实际组成

| 组件 | 实现和地址 |
|---|---|
| 前端 | `source/fingertip-legend-app`，uni-app/Vue3/TypeScript，127.0.0.1:5193 |
| 本机业务接口 | `my_legend_production.story_api`，127.0.0.1:8895；本地会话、草稿、任务、大纲确认及章节投影 |
| 原故事 API | StoryGenerate 0.3.0，127.0.0.1:8897 |
| 原故事 Worker | `DurableWorker`，使用原大纲生成、审批、正文、演绎标注和质量门 |
| 数据库 | 已安装的 PostgreSQL16 程序，独立目录 `runtime/my-legend-story/postgres-data`，127.0.0.1:55439；不连接已有业务数据库 |
| 模型 | `https://moma.cmecloud.cn/v1`，`qwen/deepseek-v4-pro`，五档统一配置 |

故事引擎固定提交为 `0dec8480e3c1b01af66407ff063f825a3fd5dedb`，源码保存在 `source/StoryGenerate-0dec8480e3c1b01af66407ff063f825a3fd5dedb`。下载ZIP的SHA256为 `9544578a2fb07711ab1f9c2ecd4d722f72f5461dfbf6dab8020a3ac8e45d0cb7`，与此前核对记录中的21份同提交源码Git blob逐一匹配。原引擎源码及质量阈值保持原样；MOMA参数和每次执行最多12次模型调用的约束通过外部Provider包装器注入。

外部MOMA适配层要求JSON输出和规范的台词类型；若正文不符合原85%–115%目标时长范围，最多调用三次原单场局部修订，并在每次修订后重新计算实际朗读字数。局部修订卡的旧字数分配同步为按实际正文计算的新预算，获批事件和原场内容保持输入证据。常规请求关闭思考；时长修订请求启用思考，输出上限至少8192 token（包括模型思考所用token），便于核对字数。非时长错误不进入该循环，三次后仍不合格则继续失败，不截断正文、不放宽门禁、不改写获批大纲。该修订会额外消耗模型额度；网络请求不自动重试。开关的实际行为以供应商返回的用量为准。

质量模型的每一项 `passed=true` 检查必须给出正文中实际存在的 `evidence_line_ids`，包括无精确钟点的连续性检查。适配层将这个原最终交付要求提前到结构化响应校验；缺失证据时，原Provider可按其已有规则带校验错误重问一次。模型不能证明时应返回不通过；适配器不生成证据、不替换结论，原连续性和交付验证继续执行。

生成时长存在明显波动。本轮一次时长修订请求约213秒，供应商报告9007个思考token；总等待还包含正文、逐场演绎标注和质量检查。百分比只表示阶段，不能用作剩余时间估计。单次模型网络读取沿用原引擎的有限超时，等待期间不要反复提交新故事来尝试加速。

原 API 负责大纲、审批和正文任务，业务接口不自行编故事。角色使用稳定的 character/role/performer 身份，但这些逻辑演绎者ID不表示已绑定实际TTS音色。大纲审批传入当前 revision 和 fingerprint，服务端核对过期版本；正文只消费冻结的审批快照。

模型Key保存在此前Windows用户加密配置中。数据库口令和内部服务凭据由本机生成并DPAPI加密，放在被Git忽略的运行目录中，仅通过子进程环境传递。前端仅持有本机业务会话，不接收模型Key或内部服务Bearer。

当前前端 `.env.local` 为以下非秘密配置：

```dotenv
VITE_USE_MOCK=false
VITE_LOCAL_BACKEND=true
VITE_API_BASE_URL=http://127.0.0.1:8895/api/v1
```

## 接口与持久化

| 业务接口 | 原 StoryGenerate 操作 |
|---|---|
| POST `/stories/{id}/generation-tasks` | POST `/v1/plans` |
| GET `/generation-tasks/{id}` | GET `/v1/tasks/{id}` 或 `/v1/jobs/{id}`，必要时读取Plan和正文 |
| POST `/generation-tasks/{id}/revise` | POST `/v1/plans/{id}/revisions` |
| POST `/generation-tasks/{id}/approve` | POST `/v1/plans/{id}/approve`，同时入队正文 |
| POST `/generation-tasks/{id}/retry` | 对应Task/Job的显式retry |
| POST `/generation-tasks/{id}/cancel` | 对应Task/Job的cancel；已提交的外部推理不能承诺撤回 |
| GET `/stories/{id}` | 已持久化章节；完成时读取原StoryDelivery及RenderManifest |

业务接口前缀为 `/api/v1`。本机草稿、会话和任务映射位于 `runtime/my-legend-story/app/app.sqlite`，模型任务与审批由独立PostgreSQL保存。正式章节保留集ID、原台词和故事版本；动作/音效以说明文字展示，不当成对白。完整 `StoryDelivery`、`RenderManifest` 按内容哈希保存在 `runtime/my-legend-story/app/artifacts/`，作品记录保留它们的版本和哈希。

脱敏运行诊断：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\my-legend\Inspect-Story.ps1
```

该命令只读，报告阶段、错误和用量，不会重试模型。日志位于 `runtime/my-legend-story/logs`。不要分享加密凭据、数据库、会话库或未经核对的原始日志。

原Worker在MOMA包装前的模型输入、模型响应和用量证据保存在被Git忽略的 `runtime/my-legend-story/model-evidence` 中，用于核对结构和质量问题；MOMA包装规则见 `run_story_worker.py`，不能将原Worker捕获的输入误当成包装后的逐字HTTP请求。这些记录可能包含用户创意和完整正文，不应作为公开交付物。对外只分享核对后的脱敏报告。

已有成功结果的接口、源文、版本和制品哈希可以只读核验，不触发生成或重试：

```powershell
& .\runtime\my-legend-story\.venv\Scripts\python.exe -X utf8 .\ops\my-legend\verify_story_result.py <故事ID>
```

## 视觉表演状态

已验证的是现有视觉LangGraph、Dart编排器、基础二维素材、音频实测时间对齐和Pillow/FFmpeg导出。旧 `local-004` 是4.7秒基础像素测试视频，使用合成测试音；声音待听审、视觉待上下文确认、发布未批准。

新故事达到READY之后，界面只显示剧本就绪，声音与视觉仍是 `not_started`，不附加旧演绎样例冒充新作品。真实演绎还需要角色外观与素材绑定、场景开场在场状态、可执行动作、实际配音和审核。基础素材档支持全剧最多6人、单场4人、2场景、100事件、90秒；站立对话档动作以入场/退场/移动/等待为主。不能将台本里的任意动作视为引擎已支持。

故事引擎的创作包可能将一处物理地点划分为三个戏剧场次；当前视觉适配器按所选 `scene_id` 计数，最多两场。因此不能仅凭“同在一个书屋”判断整集符合视觉容量，还需对实际交付场次、事件、动作和音轨逐项检查，或设计保留来源的分批制作方案。

目前没有接入生成连续视频画面的模型，没有把Flutter/Flame播放器嵌入uni-app，也没有完成Android/微信真机验收。本次实现范围为真实故事服务与H5原型接通。
