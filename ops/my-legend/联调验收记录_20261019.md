# 我的传说 · StoryGenerate 接入验收

日期：2026-10-19。范围：本机 uni-app H5、独立 PostgreSQL、原 StoryGenerate API/DurableWorker、本机业务接口，以及 MOMA 的真实模型调用。技术链路已用一个真实故事样例通过，人工内容验收为 false。

## 实际完成

原型通过业务接口调用原 StoryGenerate：创意草稿 → 大纲任务 → 查看大纲 → 当前 revision/fingerprint 确认 → 原 Worker 生成正文、逐场演绎标注和质量检查 → 正式故事版本及 RenderManifest → 故事详情与章节阅读。大纲修订、过期版本拦截、重复确认幂等、显式重试、取消和重启后的映射恢复已有代码与接口测试；真实浏览器本轮走通的是大纲查看、确认、失败重试和成功章节阅读，没有另行消耗模型额度执行一次大纲反馈修订。

故事引擎固定为 `0dec8480e3c1b01af66407ff063f825a3fd5dedb`，原源码未修改。模型和质量响应兼容通过外部包装器完成。模型Key留在后台的Windows用户加密配置中。业务入口仅为单人本机开发会话，不能当作正式账号系统。

## 联调发现及修复

两份创意均曾遇到真实模型输出不满足时长预算，失败记录保留。外部执行器最多调用三次原单场修订，每次重新计算朗读字符；统一修订卡旧预算和实际修订目标，局部修订启用思考。一次成功的局部修订请求耗时约213秒，不能承诺固定等待时间。

随后出现质量模型把时间连续性判为通过，却返回空证据列表的情况，原门禁正确拒绝交付。外部结构约束要求每项通过结论必须给出原文中的实际行号，缺少或虚构行号会进入原结构化输出纠错或失败。适配器没有补造证据、放宽时长范围、截断正文或将不合格候选改成READY。

最终第二份创意在第5次正文尝试通过；第一份创意保留在失败状态，不继续自动调用。全轮大纲与正文共有29次真实模型调用（含失败和重试），供应商报告输入151037、输出58073 token；不含此前33输入/5输出token的微型连通性探测。本次成功证明一个样例的技术链路，不能据此推断多题材成功率或生成内容已获人工认可。

## 视觉表演判定

视觉LangGraph、Dart编排/求值、基础二维素材与Pillow/FFmpeg导出具备本地技术验证；旧 `local-004` 的4.7秒MP4使用合成测试音，声音为awaiting_review，视觉为awaiting_context，发布为not_approved。今天再次核对视频SHA256为 `91c69b41038d013a795c061e31b697b8a265b8d1eb0ecf3f2f5486d78be642f4`。它不能代表本次新故事已生成音视频。

新故事尚需人物外观/音色/素材绑定、场景开场状态、可执行动作、真实音轨及实测时间轴、上下文和成片审核。当前视觉适配器每批最多2个scene_id，成功样例有3场，不能直接整集提交；需要保留原始来源和场次对应关系的分批制作方案或经过验证的容量扩展。现有站立对话动作也不能直接表现任意修灯操作。未接入连续画面生成视频模型，未将Flutter/Flame播放器嵌入uni-app。

因此：故事生成到章节阅读已跑通一个真实样例；视觉底层可继续开发联调，新故事的一键完整演绎制作尚未就绪。
